# easyedatool：嘉立创EDA工程离线工具

检查电源线中间是否仍有细颈：在该板的规则文件 `[drc.quality]` 设 `width_neck = 0.3`（起查线宽，毫米）、`width_neck_min_length = 0.25`（最短连续长度，毫米）和 `width_neck_nets = ["+3V3", "+2V8"]`（按实际网络改，支持 `*` / `?`），运行 `easyedatool drc <工程> --rules <规则.toml> --json <报告.json>`。按实际最小电源线宽选起查值：它不是目标宽度，设得高于两端粗线会漏查（例如 0.4 会漏掉 0.3→0.127→0.3）。工具从起查值逐档检查实际线宽；字段为 0 时关闭，不填网络列表则检查所有网络。

默认的 `width_neck` 只查同层、没有焊盘、过孔和分支的连续链。复查电源时再设 `width_neck_through_contacts = true`（默认 false），检查 `routing_quality` 的 `width_neck_contact`：它沿只有两个可辨认露铜端口的实际焊盘/过孔接点贯穿，按真实层跨度处理，并扣除铜覆盖长度；两端须实际接到更粗走线，铜环/焊盘本身不算粗线。单端细引脚出线不会仅因接到大焊盘而报细颈。混合粗细分支、重叠接点和不明确搭接仍需人工逐层核对，不得凭两类提示均为 0 宣称已检查全部电源。按报告层、坐标改宽或改道，改完重算铺铜，复查间距、断网、差分和窗口截图；`width_bulge` 为 0 同样不能代替这些检查。

窗口里手工添加线路或过孔时，工具先检查整个候选的铜间距、跨层过孔、板边、孔距和禁布区；新增违规会拒绝整次写盘，原 PCB 不变。推挤后的邻网线也参与检查。分步布线完成后仍须 `pour --write`，再用项目规则跑 `drc` 检查连通、悬空和布线质量，不能只凭窗口预览判断。

同一个引脚号有多个实体焊盘时，修改铜的连通保护按焊盘位置和铜层区分实体，不把同名焊盘误认成另一块铜上的接点。原有断网仍须处理；不增加断网的检查通过，也不表示整板已经连通。

设计文件 `[rules] smd_pad_clearance = 0.15` 只改工程默认安全间距表的「贴片焊盘到贴片焊盘」一格（毫米）；需先核实器件焊盘实际间距和板厂能力，不能借此放松焊盘到走线、过孔等其它间距。设置后重新 `gen`，跑不带 `--clearance` 的 `drc` 确认工程规则下的结果。省略该字段时保持 EDA 默认值；这不是 `route --rules` 的字段。

元件库封装的槽孔与原厂推荐图不符时，可在设计文件用 `[[library_pad_patches]]` 指定 `footprint`、`pad`、`hole_width` 或 `hole_height`（毫米，嘉立创焊盘的局部轴），例如 `pad = "3"`、`hole_width = 1.2`。`gen` 只改本工程嵌入的封装，不改共享库；找不到对应孔会报错。改后核对原厂图、生成板的钻孔与 DRC，不能拿修孔尺寸代替实物装配验证。

贴片焊盘不能默认打普通通孔。项目规则 `[drc.quality]` 填 `via_pad_clearance`（毫米，正值；例如 0.10，须按项目工艺确认），`route` 会连同本网络焊盘一起避开，先引线后换层；默认 0 是兼容旧行为。`via_pad_allow` 只填有工艺依据的具体 `位号.脚号` 例外，不能把全部 GND 或全部焊盘列成例外。跑不带 `--clearance` 的 `drc --rules ... --json ...`，逐条看 `routing_quality` 的 `via_pad`，该项是工艺复核提示，不是电气短路错误。它覆盖原有孔和无走线的孔；输入保留铜、手动布线、差分 `pair` 不会被 `route` 自动挪走。未处理完的提示必须列入交付说明，不能只报「电气 DRC 通过」；交生产前应为 0，或逐项有明确工艺依据。过孔从焊盘上移开时重建出线，再查所有层的间距、连通、差分与等长。

修复已有焊盘内过孔用 `escape-vias <工程> --rules 规则.toml --radius 2` 试算，再加 `--write` 写回；`--net` 可重复指定。读取 `via_pad_clearance` 和例外，联合重接过孔各层引线，保留原孔径、跨度、阻焊属性；每个候选查全板连通与间距。差分/等长、锁定网络和含圆弧的网络不修改。半径0不修改。报告「暂未找到安全出线」表示该孔仍待处理，不能宣称已经修复；写后重算铺铜、保存布局，查外部规则的DRC、孔位和转角。不能用增加豁免掩盖普通焊盘内过孔。

该命令先检查孔是否多余：普通网络仅在一面有铜连接、不承担铺铜或缝合作用，而且删孔后全板连通及已启用的布线质量检查不变，才删除并输出「移除无须换层的过孔」。另一层没接线只是候选条件；同层两段线可能只靠铜环连通，这种孔不能直接删。看到删除提示后同样必须重算铺铜、保存布局、复查DRC并看实际窗口。

短鼓包检查及 `widen --smooth` 同时覆盖接到焊盘中心的末端宽线：须确实落在焊盘铜内，缩细后逐一确认原有接点仍在。若同网有效过孔或电镀通孔的另一覆盖层有同宽/更宽走线伸出铜面，则属于跨层连续主干，不作为孤立末端鼓包报告或缩细；孔径、铜内短记录、未被孔跨越层上的粗线不算支撑。长电源主干不因末端短鼓包而统一缩细。

用户指定整网同一线宽时，用 `widen <工程> --uniform --net 网络名 --width 毫米 [--rules 规则.toml]` 试算；成功须看到「统一网络线宽」和「全部检查通过」，再加 `--write`。可以重复 `--net`，所有指定网络、全部铜层作为一批检查和写回；任一冲突就不写，不能自动降低目标宽度或只改一部分。线宽按文件精度 0.001 mil 取整，输出实际值。锁定的待改走线或圆弧会拒绝，不能绕过检查删记录。窗口「开始改」后右键走线 →「统一 … 的线宽」，属性栏同样有按钮；API `net_width` 的 `net`、`width` 一次改一个网络，支持一步撤销。该操作不挪过孔、不重布，写后重算铺铜、保存布局并用项目外部规则查 DRC；电源线目标宽度由项目载流需求决定，不能仅为消除鼓包擅自把全网缩到最细线宽。
同一小焊盘连接的两段线、另有中心线连接的过孔，按实际铜连通复核冗余圆头搭接。`escape-vias` 的孔距使用项目 `via_spacing` 和 `[drc.fab] via_hole_to_hole`，候选不得增加偏心、绕行及已启用的转角/鼓包提示。修复后必须重跑 `drc` 并看最新窗口；报告「焊盘避孔修复 N 个」计入此次移动和安全删除的数量，不表示所有遗留问题都解决。

普通线路出现连续小台阶时，用 `clean <工程> --rules 规则.toml` 试算；报告「整理直角 / 连续小台阶 N 处」，检查通过再加 `--write`。规则 `[drc.quality] corner_angle` 和 `corner_cut` 任一为 0 时不改拐角；`--net` 可以重复指定网络。偏心过孔已由铜环接通、孔位又不能安全移动时，加 `--center-vias`：只在原铜环内补中心引线，报告「过孔铜环内中心引线 N 段」；放不下或引入急弯时不补，仍须核对剩余 `via_offset`。这不移动过孔、不替代真正的绕路检查。差分/等长、锁定网络不会修改，不能以此命令成功宣称全板已无直角。写后重算铺铜、保存布局，再查 DRC 和窗口实际几何。短鼓包接着焊盘时，`widen --smooth` 逐一检查缩细后是否仍接到原焊盘，丢接点时不修改；独立分支仍保留。

差分出线同时规划芯片和连接器。多对一起用 `pair --pair A --pair B --replace --write`：先共同预留焊盘到过孔及另一层到并排出口的短线和出口空间，后布主干，最后做对内等长。出现「出线规划」只说明已经预留孔位，不代表布通；整批成功才会写回，失败时不能报告已画完。过孔尺寸读工程默认规则，没有有效规则用 0.5 / 0.3 mm；自动换层目前只适用于顶层器件转到底层，`--no-via-fanout` 关闭细间距端自动换层。两端引脚顺序交叉时，可用 `--same-layer A` 让所选 A 的主干留在 `--layer`，其余对仍自动换层；A 必须也出现在 `--pair` 中，层分配记在工程的布线命令中，不写进工具源码。双排连接器的远排引脚仍可换层接回。布完跑 `constraints` 查对内长度差；跨对等长需求另加 `length_rule` 和 `group`，再 `tune --group 组名 --write`、重算铺铜、跑 `drc`，报告实际长度及未通过项。

画板不用操作 EDA 客户端：写一个**设计文件**（器件、网络、位置），工具生成原理图和 PCB、布线、铺铜、检查，结果都是文字报告。

窗口放大后默认显示走线网络名，图层栏「走线网络名」可关。Ctrl + 单击走线 / 过孔 / 焊盘追加或取消网络高亮，Esc 清空；多个网络分别着色。高亮按真实线宽和孔径画，保留钻孔，不把显示加粗造成的搭接当成真实短路。窗口拖孔会尝试推挤普通邻网走线（`via_move` 的 `shove: true`；省略或 `false` 保留只移动检查），覆盖孔跨度内所有铜层；孔中心在线段中心线上、只有一小截线尾完全落在孔铜内时，拖孔会收掉该短尾并带走接点。锁定相连线、偏心搭接或穿过孔的长线中部实际分支仍拒绝。被挤开的邻线保留原线宽和固定端点，受差分 / 等长约束的邻网报「需要成对规划」，不会单独挤开。自己的端点跟随尚不保证重新形成 45° 引线。候选按工程内部规则预查间距、孔距、板边、禁布区、连接和差分 / 等长约束，出现「移动过孔会新增或改变…」「需要先重建接点」时表示没写入，不能报告已移好。完整收回的短引线删除，不保留零长度段；成功后一步撤销恢复全部受影响层。修改后仍要重算铺铜，并用该工程的外部规则文件再跑 DRC；不能绕过拒绝直接改文件来模拟推挤。

布通以后仍要看 `drc` 的「布线质量提示（不计作电气 DRC 错误）」及 JSON `routing_quality`：`via_offset` 是铜环碰线但孔中心偏离，`via_detour` 是过孔引线旁有较短候选通道。按报告的网络、层、坐标定位；不能直接照候选移孔，要检查所有层、分支和网络专用规则，再重算铺铜、重跑 DRC。默认不把差分 / 等长网络的蛇形当绕路；`[drc.quality] include_constrained = true` 开启专门复核。电源新布时可设 `power_min_run = 0.8` 抑制短加宽鼓包（0 保留旧行为），已加宽的输入不会自动缩细；整理旧鼓包用 `widen <工程> --rules 规则.toml --smooth`，须设 `power_min_run > 0`，先看报告的「整理短鼓包 N 段」及线宽×长度，再加 `--write`，随后重算铺铜并查 DRC。该选项收回夹在两段细线之间的孤立加宽段，也可收回一端精确接到过孔中心、另一端接细线的短加宽段；保持孔径和铜环不变，保护焊盘、偏心过孔和分支搭接。差分候选已经计入换层出线，并先比较较长成员以减少后续补长度，但仍须核对差分间距和等长，不能仅凭线路变短判成功。

`power_min_run` 量的是同层同网络、中心线端点相接的连续新加宽段：跨多条 LINE 记录累计，细颈或换层处断开。`route` 与 `widen` 用同一判断；设 0 保持旧行为，已有宽线不会被它缩细。阈值由当前板的规则文件确定。试算后核对各电源网的“线宽×长度”，再放大查看残留细颈和短鼓包；质量提示为 0 仍不能代替看图。

- 程序：本目录下 `bin/easyedatool.exe`（Windows x64，模板都编译在里面，不需要别的文件）。下文的 `easyedatool` 都指它，命令里写它的完整路径。
- 源码：`E:\project\EasyEdaTool`（公司内部仓库 miyue/EasyEdaTool）；别的系统在源码目录 `cargo build --release`，用 `target/release/easyedatool`。
- 参数全集：每个命令加 `--help`（中文）；汇总在 `references/commands.md`。
- 写设计文件：`references/design-format.md`，照 `examples/demo.toml` 改。
- 布线 / DRC / 核对规则文件：`references/rules-format.md`，例子 `examples/demo.rules.toml`。
- 用户同时开着 EDA 客户端：`references/eda.md`。
- 给人看的完整说明（速度、和 EDA 的核对记录、已知限制）：`README.md`。

整板3D：`render3d <工程> --download-models -o <图.png>`，成功输出「3D板厚 … mm，元件 … 个（真实模型 …，外形估算 …）」；去掉下载参数可离线复用缓存。`-o <模型.glb>` 导出带颜色的自包含模型，`-o <模型.stl>` 导出无颜色的二进制STL毫米网格；STL导入时选毫米，GLB按glTF标准使用米和y向上。要求两种格式时分别保留，按单位换算后核对外包尺寸、安装孔及位置一致；`--json <场景.json>` 留几何和各器件准确性记录。窗口点击「3D」或 `view <工程> --3d`，拖动旋转、Shift拖动平移、滚轮缩放，可看正反面和四侧、模型清单、高亮定位及导出。截图验收用窗口 `--3d --snapshot`，它等待首张3D图到达。必须实际打开图核对连接器朝向、口沿与板边；缺模型会标「近似外形」，不能声称其高度、外壳尺寸已验证。3D无模型碰撞检查，不代替实体装配和DRC。毫米OBJ及尺寸覆盖在工程 easyedatool.toml 的 `[view3d]`、`[view3d.parts."位号"]` 或 `[view3d.footprints."封装名"]`，参看README「整板3D」。工程文件和共享库不被3D修改，缓存 `.easyedatool/3d/` 不提交。

3D元件看起来偏离焊盘时，先比较PCB焊盘中心与模型定位，不得移动电气几何去迁就模型。默认对称两端SMD模型须通过同形焊盘、无孔、居中本体和匹配尺寸检查才自动按焊盘中心对齐；输出“已按对称焊盘中心修正 N 个模型的定位；未改PCB坐标”，清单有修正前后偏移。特殊件 `alignment="library"` 保留库偏移；`"pads"` 显式按焊盘中心。连接器、多脚和非对称件默认不改，修正后实看正反面和旋转方向并核对铜哈希。

## 安装孔与3D交付核对

导入板子的不贴装器件、无实体标记，在工程`easyedatool.toml`的对应`[view3d.parts."位号"]`设置`hidden=true`，只从3D装配排除，保留PCB焊盘和网络；须有BOM/标记类型依据，不按空Value猜。仅用于兼容占位、尚未核实实物匹配的外部OBJ设置`approximate=true`，模型清单仍标为近似。用`render3d`输出和实际窗口复查隐藏数量、位号、模型位置；用法及端子CAD来源见[模型与焊盘说明](references/models-and-pads.md)。

开关电源变压器先读[变压器参数、绕制与3D来源](references/transformers.md)：按拓扑及工况设计电气参数，确定磁芯、材料、气隙和骨架后输出绕制规格书，再配封装与3D。EE/PQ等外形名称不能确定功率、匝数或脚位。当前`smps`检查版图，`thermal`按给定绕组DCR、有效值电流和磁芯损耗估算发热，尚无自动磁件设计命令；厂家设计工具和CAD入口见该参考。只询问方法时先解释流程和来源，不自行选定电源工况或开始绕组设计。

TO-220 MOS管、肖特基管的散热器，先读[散热器和机械件封装](references/heatsinks.md)里的获取渠道与截面图流程：优先找同型号模型，只有截面图时按尺寸重建并拉伸、开孔。当前工具尚无任意截面拉伸和实体开孔命令，需用外部CAD生成模型再转换绑定。用户只是询问哪里能找到时，先回答渠道与格式，等实际制作时再确认采购规格。

散热器、隔离柱等无焊脚机械件可在自建封装中显式设`mechanical=true`、`pads=[]`及正数宽高的`outline`，保留完整外框；普通封装仍须有焊盘。先按型号核对机械尺寸，再用参数配方或毫米OBJ绑定。`examples/heatsink.toml`提供可生成的机械件示例。厂家STEP须先转换，不能把参数STEP导出说成原厂CAD直接导入；KiCad封装、DWG/DXF当前也未提供一键导入。步骤及验收见[散热器和机械件封装](references/heatsinks.md)。

按规格书和照片补模型时，使用通用`model3d box`、`cylinder`命令组合实体，`color`改RGB颜色，`export`出PNG/OBJ/GLB/STL/STEP，`bind`试算后加`--write`绑定位号。规格书尺寸及公差、照片近似配色分别记来源；成功须看到「参数模型已保存/已导出/参数模型绑定」。参数模型不得冒充原厂CAD，须查看实际正反面预览并核对位置和高度。下载封装的焊盘用`pad-edit`改铜面尺寸、增减或缩放，默认试算，`--out`输出副本；保留丝印与孔，不给正式已布板试尺寸。新丝印干涉须调整完整轮廓，不能删框。项目的`library_pad_patches`可设`width`/`height`，它们是铜面，`hole_width`/`hole_height`才是孔。完整步骤、命令及边界见[参数模型和焊盘修改](references/models-and-pads.md)；先查`--help`，已发布0.2.3尚无这些开发版命令。

机械安装孔须逐项核对设计坐标/孔径、PCB原生孔、NPTH钻孔文件及3D板体：圆孔和槽孔必须真实挖穿并有孔壁，不能用黑色圆形贴图冒充。孔位与尺寸从项目读取，不写死进通用渲染代码。若仅3D漏孔，修渲染并重新导出PNG/GLB/STL、刷新Flutter预览，不为迁就模型改动实际孔位；核对最新正反面及斜视图。

只改已有圆形安装孔孔径时，先在设计文件的 `[[board.holes]]` 修改毫米直径，保留孔心，再用 `holes <工程> --design 设计.toml --rules 规则.toml` 试算。必须看到「孔距 / 铜间距 / 板边检查通过」后才能加 `--write`；缺孔、重复匹配、工艺或间距冲突须先处理，不能用脚本改原生记录。命令不移动、新增或删除孔，也不扩大螺钉头禁布区；写后 `layout --save`、项目 DRC，并重导生产钻孔、二维图、GLB和STL，核对孔径与孔心一致。须先查 `holes --help`；已发布的0.2.3尚无此开发版命令，不能假定旧安装包支持。

## 元件丝印与布局的交付约束

**新画板、重新布局和修改封装时，必须保留各元件的本体丝印及必要方向标记，并保证丝印不打架。** 这些约束适用于所有工程，不以用户再次提出要求为前提；元件范围、尺寸和间距写在项目设计/规则中，不能在工具代码里写死某块板。

- 先列全板清单：位号、安装面、位置/角度、本体轮廓、是否完整、1脚/极性标记及冲突对象。矩形阻容和芯片保留完整外框；连接器按实际封装保留开口外形和插入方向，不能用一小段线冒充完整本体。
- 丝印不能与相邻元件轮廓、本体、方向标记、开窗或板边干涉。遇到冲突，调整元件位置/方向并重接相关线路，重铺铜、保存布局后复查；**禁止通过删框、裁短、隐藏丝印层、删除方向标记/外框约束，或降低安全间距来消除报错。**
- 新生成的设计启用 `[body_silk] enabled=true`、`require_all=true`，按器件类型配置 `frames`、`pin1`、`cathodes` 和项目间距。库原丝印只有在项目内完整替代并验证后才可省略；完整外框和方向标记不能再被自动避让裁掉。仅检查第三方原板时先清点现状，不擅自改写。
- 交付前，DRC的丝印、外框缺边/冲突及元件间距错误必须为0，框数和方向标记数须与清单对应；还要查看实际顶/底层Gerber及最新PCB预览。电气DRC通过不代表丝印完整，没有检查就不能宣布完成。
- 用户明确允许时可不印位号文字，但本体外框、芯片1脚、二极管/LED负极条仍保留，全部位号继续进入BOM、坐标和装配图。

配置、清单与复查步骤见 [元件丝印与布局约束](references/silkscreen.md)。发现元件无本体线、缺边或丝印打架时，先修正再导出生产包。

STM32MP157 示例按用户确认的范围处理：保留 ST 参考核心的密集布局，核心阻容使用避开阻焊开窗的常规丝印，外围保留完整外框和方向标记。不要为给核心阻容加完整外框而重排原厂 DDR / 电源布局；补线所需的局部调整、走线和铺铜保存在示例的布局文件中，按示例自己的构建步骤恢复。

## 规矩（先读）

重新生成后核对位号是否留在原处。布局文件的 `label_style` 保存文字定位原点、字号、笔宽及显示状态，避免居中标签在再生成后偏移；由工具保存和恢复，不要手工改。旧布局可读，运行 `layout <工程> --save` 从当前板子补记样式。

用户要求窗口验收时，交付前必须使用窗口自己的 `--snapshot` 截取当前工程的整板图和问题位置的放大图，并实际打开图片核对。截图默认放临时目录，不加入工程或提交；用户要求不保存时，对比后清理临时截图，只保留 PCB 预览。`render` 的离线图、`/api/board` 一致以及 DRC 通过都不能代替窗口截图；截图失败或未查看时只能报告尚未完成显示验证，不能宣布窗口验收完成。核对时确认 PCB 文件哈希，图片中应能辨认目标网络、实际线宽和过孔孔口。全板看出疑似粗细交替后，要逐层核对：细颈可能跨过焊盘或过孔，自动无分支链检查不一定覆盖；用通用走线宽度编辑检查整个连接的候选，受阻就保留并列明，不能只凭质量提示为0宣称全部消除。修改以后重新截图、查 DRC 并保存布局。

用户说“香肠线”仍在时，先核对窗口工程路径和磁盘几何，再检查实际线宽；不能以 `width_bulge` 为0代替看连续线路。`widen <工程> --rules 规则.toml --bridge-necks 3` 试算连续主干加粗/改道，`--net` 可重复指定，参数是端部原细线最大保留长度（mm），按项目设置，0关闭。它优先试规则 `power_track`，再试不超过目标的0.4/0.3mm，不得缩细该链原有宽线。单条长直线和多段全细主干也参与，不能只找“粗—细—粗”；但总长未超过两端允许保留出线范围的短支路不处理。成功报告“细线主干 A → B mm”或“线宽跳变 A → B”，受阻报告“未找到安全加宽路径”或“未找到安全连续路径”。成功条数不是全板完成数。只有输出“检查通过”才可加 `--write`；写后 `pour --write`、`layout --save`、`drc --rules`，并核对最新图形。加粗可能切断原来的地铜通道，必须检查重铺后包括GND在内的连通，不能只查旧填充。差分/等长网络不参与，锁定走线/圆弧拒绝；原过孔记录保留。不同时用 `--smooth`、`--uniform` 或 `--width`。

改层数或重新布线以后，重新核对规则 `[nets] power`、目标 `power_track` 和各电源实际线宽×长度；新改成走线供电的网络也加入项目的 `width_neck_nets`。恢复布通不代表已经恢复电源宽度，不能沿用旧板的加粗报告。整条同宽细线不一定触发细颈检查，应单独核对长细主干与必要引脚出线。

推挤固定原走线中途接入的支路、过孔和焊盘接点，不能只固定两个端点。若报告“原有焊盘、过孔或分支接点无法全部保留”或“固定接点之间绕不开新线”，候选不能写入。改完必须查受影响邻网的连通，例如开关支路不能因为主路径还接着而漏查。`widen --smooth --write` 现在只替换走线记录，不重新生成过孔，写前重读实际文件检查连通和间距；写后仍须重算铺铜。

`widen --smooth` 的报告还会列出「清掉覆盖线 N 段」：只删被同网同层另一段铜完全覆盖的记录，不删真正分支或更宽的铜。目标网络有锁定铜时会拒绝修改。写回后重算铺铜、检查断网和差分约束，再保存布局；只有报告通过，才能说整理结果可保留。

同一条无分支中心线拆成不同宽度记录后，圆头会跨过短颈缩互搭；整理时沿 `power_min_run` 范围内的精确端点链确认这种情况，不把它误当旁支。真正的偏心旁支、焊盘以及偏心过孔搭接仍保护，报告里剩下的鼓包需要逐项核查。

用户指出直角或“香肠线”时，不能拿过孔检查的 0 条作为已清理干净的证据。在 `[drc.quality]` 配置 `corner_angle = 100.0`、`corner_cut = 0.2`、`width_bulge = 1.6` 后运行 `drc --rules ... --json ...`，逐项查看 `sharp_corner` 和 `width_bulge` 的网络、层、坐标。角度和鼓包长度阈值默认 0（关闭），这些数值只是可调整的筛查尺度。差分转角候选必须复查两根线和全组等长；没有候选表示局部受阻。鼓包连着焊盘 / 过孔或分支时不能直接缩细。报告实际剩余数量和原因，再核对窗口服务的 `/api/board` 与磁盘铜几何一致；旧截图不代表当前窗口。

差分 / 等长网络默认还检查非局部相邻铜线的自身搭接：`[drc.quality] self_crossing = true`，设 `false` 关闭。JSON 种类 `self_crossing` 同时包括中心线相交和中心线未交但铜边搭接；局部端点连接、短倒角的圆头重叠及孔 / 焊盘内接点不报。它属于布线质量提示，不改变传统电气违规条数；出现此提示时不能以线段总长判定等长成功，须先修复搭接再调长。`tune` 调长时将相邻整段同网走线及本轮已经生成的蛇形线纳入障碍检查，只有正在替换的一段豁免，防止补长又碰回自己。

1. **会改写工程的只有七个**：`gen --out`（sch/、pcb/ 整个换掉，索引就地覆盖）、`route`（删掉**全部**走线、过孔、铺铜填充重新布）、`pour --write`（换掉铺铜填充）、`constraints --write`（只改网络记录上的差分对 / 等长组 / 网络类字段、这两类规则和规则指定，索引版本号）、`tune --write`（把要绕的直线段换成蛇形线，索引版本号）、`pair --write`（这对原来的走线过孔换成新布的，索引版本号）、`repair`（只改换行、BOM、索引版本号，删空临时文件）。跑之前看工程在不在 git 里、有没有没提交的改动，有就先问用户要不要提交；改坏了用 git 回滚。用户的规矩：**就地改原工程，用 git 提交和回滚，不要复制出 V0.2 这样的新目录**。
2. `route` 只用在生成的板子上，或者用户明确要全板重布：手画的板子一跑，手工走线全没了。
3. 其余命令都只读：`info`、`pads`、`render`、`check`、`erc`、`drc`、`pour`（不带 `--write`）、`constraints`（不带 `--write`）、`impedance`、`tune`、`pair`（不带 `--write`）、`pdf`、`netlist`、`bom`、`fab`（只写到 `-o` 给的地方）。`lib` 不碰工程，只写元件库（见「做库里的新元件」）。
4. 用户的 EDA 客户端开着这个工程时：**先让 EDA 关掉要改的页面（PCB 页），再跑写文件的命令，跑完再打开**，否则 EDA 看不到新内容，还可能把内存里的旧版本存回去。细节见 `references/eda.md`。
5. `drc`、`check`、`erc` 查出问题时退出码是 1：那是检查结果，不是程序出错，读输出改问题。
6. 路径：工程文件夹、`.eprj3` 或 `.epcb2` 都能当输入，中文路径没问题；Git Bash 里用正斜杠或加引号。
7. PCB 坐标一律毫米、y 向上（和 EDA 界面一致）；原理图里自建符号的引脚坐标是 EDA 图纸单位（10 mil）。
8. 依据文字输出核对电气和连接结果；丝印完整性、布局和外观验收还必须查看最新PCB预览及实际Gerber。窗口验收按前述截图规则，不得以报告代替看图。
9. **在 Windows 上别用文本方式写工程文件**（Python `open(f, "w")` / `write_text`、PowerShell `Set-Content` / `Out-File`、记事本另存）：会写成 CRLF 换行或加 BOM，嘉立创整个文件读不了，PCB / 原理图打开是空的，关工程时还会删掉索引里的版本号。非改不可时二进制读写、保持 LF，改完跑 `easyedatool check <工程>`，「工程文件」那行要是「没问题」。用户说「嘉立创打开 PCB 没了 / 原理图是空的」，先跑 `check`，报 CRLF 之类的错误就请用户在 EDA 里关掉这个工程，再 `easyedatool repair <工程>`，然后请用户重新打开。
10. **AI 和人轮流改**：用户在预览窗口里点了「开始改」时，改工程的命令（`gen`、`route`、`repair`，带 `--write` 的 `pour` / `place` / `tune` / `pair` / `widen` / `constraints`，`layout --save`）报「预览窗口里有人在改这个工程（… 开始，…）」就不跑——这不是出错：停下来告诉用户，等用户在窗口里点「改完了，交给 AI」再接着干，别反复重试，也别绕过去直接改文件。接着干之前先读工程里的 `.easyedatool/edits.log`（人挪了、转了、翻面、锁定了哪些器件），照它调整下一步（见「别的常见活」的「人在窗口里改过以后接着干」）。每一轮开始也跑一次 `easyedatool review <工程>`：用户在窗口里写的审核意见在那里（见「别的常见活」的「处理审核意见」）。

原理图文字可通过 `POST /api/edit/sch` 的 `caption` 操作单独挪动：`{"op":"caption","page":1,"part":"J1","at":[300,-600],"to":[250,-640]}` 移位号，另加 `"value":true` 移值。坐标是图纸单位；只改文字位置，符号和连接不动，支持撤销和再次生成。先 `/api/edit/start`，改完 `/api/edit/done`；成功回包的 `undo_what` 包含「的位号挪到」或「的值挪到」，再 `gen`、`check` 和出图核对文字位置及网表。不改电路的原理图编辑只重画原理图，PCB（含走线、过孔、约束和铺铜）逐字节保留。窗口尚无独立拖文字入口。

`library_silk_omit` 只用于用项目完整本体轮廓替代库原丝印，不能作为消除干涉的方法。它也会省略库的图形方向标记，必须用项目 `body_silk` 恢复完整外框、1脚和极性条，按清单逐项核对后才可交付；详见 [元件丝印与布局约束](references/silkscreen.md)。

让预览自动检查采用项目规则：在工程旁的 `easyedatool.toml` 加 `[checks]` 和 `rules = "项目.route.toml"`（相对该配置文件）。`serve` 从工程目录逐级向上查找；显式 `serve --rules` 优先，`--no-drc` 禁用自动检查。窗口不另读 EDA 格式，规则由 Rust 后台加载。未配置时保持通用默认；路径错或类型错会报错。改配置后重开预览，复查 `/api/info` 的自动 DRC 与按同一规则运行 `drc` 的结果。

## 命令一览

| 命令 | 做什么 | 常用写法 |
|---|---|---|
| `info` | 板子概况：尺寸、器件、焊盘、走线长度（按层）、过孔、铺铜是否已填充、网络；也认 PADS 导出的 `.asc`（多一行自检：走线两端落在焊盘上的「对不上 0 处」才算读对）和 Altium 的 `.PcbDoc`（多一行读了哪些图元、没读的） | `easyedatool info <工程>`、`easyedatool info 板子.asc` |
| `pads` | 焊盘 CSV：位号、脚号、网络、中心、尺寸、转角、层、钻孔 | `easyedatool pads <工程> --part U1` |
| `footprint` | 画封装 / 量封装：标准名或设计文件里的封装，打印量出来的脚间距、两排中心距、焊盘表、设计文件写法，`-o` 出预览图 | `easyedatool footprint list`、`easyedatool footprint SOIC-8`、`easyedatool footprint 设计.toml --name QFN32 -o 看.png` |
| `gen` | 设计文件 → 整套工程，默认顺带算好铺铜 | `easyedatool gen 设计.toml --out <工程文件夹>` |
| `check` | 工程文件嘉立创读不读得了（换行、BOM、坏行、索引版本号）、器件重叠 / 伸出板外、原理图没接上的导线、没带网络名的导线（嘉立创会拆成 `$…` 网络）、原理图和 PCB 逐脚网络 | `easyedatool check <工程> --rules 规则.toml` |

## 画一块新板（最常用）

1. **写设计文件**：复制 `examples/demo.toml`，按 `references/design-format.md` 改。要点：
   - 板框 `[board] outline`，毫米。
   - 符号：芯片、连接器用自建符号（`[[symbols]]`，`left` / `right` 两列引脚）；电阻电容电感二极管 LED 测试点用内置的（`RES` `CAP` `IND` `DIODE` `LED` `TEST_POINT`）。
   - **封装按这个顺序选**：① 标准名直接写在器件的 `fp` 里（`easyedatool footprint list` 列出全部：`SOIC-8` `TSSOP-20` `SOT-23-6` `SOT-223` `LQFP-48` `R0805` `C1206` `HDR-2x5-2.54` `DIP-8`……，以及内置的 `R0603` `C0603` `R0402` `C0402` `L0402` `L0603` `LED0603` `SMA` `TP0.5`）；② 没有的，写一个 `package` 形式的 `[[footprints]]`，只填数据手册推荐焊盘图上的数（脚数、脚间距、两排中心距、焊盘长宽、本体），坐标工具算；③ 实在不规则的（连接器、模组）才手写每个焊盘的坐标。写法见 `references/design-format.md`。
   - 每个器件 `[[parts]]`：`ref` 位号、`sym` 符号、`fp` 封装、`value`、`nets = { 脚号 = "网络名" }`、`group` 功能块。**`group` 每个器件都要写，至少定义一个 `[[blocks]]`**（只有一个功能块也行）。
   - 位置：芯片、连接器、大器件给 `pcb = [x, y]`（封装原点在板上的位置，毫米）和 `angle`；小阻容可以不给，在功能块的 `regions` 里自动排。自动排的格子默认 0603 大小，大器件不给位置会叠在一起，要么给 `pcb`，要么写 `cell = [宽, 高]`。两种可以混用。
   - **符号的脚号必须和封装的焊盘号一一对应**（网络按号连到焊盘）。内置 `DIODE` 是 1 = 阴极 K、2 = 阳极 A；`LED` 反过来，1 = 阳极 A、2 = 阴极 K。
   - 接地铺铜 `[[pours]]`，禁布区 `[[regions]]`。
   - **封装最容易错，工具查不出它和真器件对不对**，照下面「封装检查单」做。
2. **生成**：`easyedatool gen 设计.toml --out <工程文件夹>`。设计文件写错会直接报错并说哪一项（未知符号、脚号不在符号上、位号重复……），改了再跑。
3. **核对**：`easyedatool check <工程文件夹>`，再 `easyedatool erc <工程文件夹>`（`gen` 跑完已经自动查过一遍 ERC）。
4. **规则文件**（布线用）：复制 `examples/demo.rules.toml`，至少写 `[nets] pour`（铺铜网络）和 `power`（粗线网络），禁布区照设计文件再写一遍 `[[keepout]]`。
5. **布线**：`easyedatool route <工程文件夹> --rules 规则.toml`。
6. **DRC**：`easyedatool drc <工程文件夹> --rules 规则.toml`。
7. **出文件**：`fab`、`bom`、`pdf`；要看图用 `render`。

改了电路就改设计文件、从第 2 步重来（`gen` 会清掉布线）。设计文件里写了 `[project] time` 的话，同一份设计每次生成的文件一模一样，git diff 只显示真改动。

### 封装检查单

机械孔单独写在设计文件的 `[[board.holes]]`：`at`、`diameter`，可选 `keepout_diameter`（螺钉头全层禁铜直径）。坐标和尺寸属于项目，不能写死在工具中；它是 NPTH，不用虚构原理图器件或加入采购 BOM。加完须核对 `fab` 的非金属化钻孔孔数、直径、孔心，并检查孔及螺钉头与器件和铜线的冲突；已有布线不会自动避让。参见 [设计文件格式](references/design-format.md#board)。

1. 能用标准名就用标准名，但标准名是**典型值**：跑 `easyedatool footprint <标准名>` 看它量出来的脚间距、两排中心距、焊盘大小，和这颗器件数据手册的推荐焊盘图对一遍，不一样就写 `package` 形式的 `[[footprints]]`（同名会盖过标准名）。
2. `package` 形式：数字全抄数据手册的推荐焊盘图（land pattern / recommended footprint），不要凭印象估。`span` 是两排**焊盘中心**的距离（手册常给外沿或内侧距离：中心距 = 外沿 − 焊盘长 = 内侧 + 焊盘长）。
3. 手写焊盘（不规则封装）：原点放本体中心，焊盘坐标是焊盘中心，y 向上，负数正常；`outline` 是本体轮廓（也画成丝印框），焊盘可以伸出去，但一般压着它。
4. **每个自己写的封装都跑一遍** `easyedatool footprint <设计文件> --name <封装名>`：它从放好的焊盘量出脚间距、两排中心距、焊盘外沿，和数据手册的数一致才算对（不用自己算坐标）。
5. `gen` 输出「注意：封装 X：焊盘 … 没压着外形框」：手写的坐标或外形框多半写错了，按 3、4 查；SOT-223 这类引脚伸得远的封装本来就这样。

### 怎么算成功

| 步骤 | 输出里要看到 |
|---|---|
| `gen` | 第一行是工程路径和器件数；「原理图 N 页：出图框 0，压标题栏 0，重叠 0」；「铺铜 N 块算好填充写进工程」；没有「注意：封装 …」（有就按检查单核对）。「位号没地方放、藏起来了：…」只是提示 |
| `check` | 「网表 … 逐脚差异 0」，最后一行「全部通过」 |
| `erc` | 「致命错误 0、错误 0」，最后一行「全部通过」；「引脚悬空」的脚确认是故意不接的，写进设计文件的 `nc` 重新生成 |
| `hookup` | 每颗芯片「错误 0、警告 0」，最后一行「全部对上」；「接法：…」认出来的接法和设计意图一致（比如该用 DC2 却认成「不用 DC2」就是接错了）。「没写额定电压」是提示 |
| `route` | 「连接 N，布通 N，没布通 0」，后面没有问题清单 |
| `thermal` | 每个器件、每个网络「合格」，最后一行「全部在限值内」；「缺参数」照它说的补；「可能超」是没给 from / to、按整网电流算的，给了再看；规则文件里「没用上」的键多半拼错了 |
| `si` | 每根网络、每个接收端「合格」，串扰每根受害线「合格」，最后一行「没有超的」；「叠层：工程里没有……」或叠层是导入的默认值时绝对数不可信，先问用户要板厂叠层；「驱动 …（引脚最多的芯片）」方向不对就用 `--driver` / 分组的 `driver` 改；有 IBIS 时看每个脚「IBIS …：模型，…选的」：选的模型电压不对（「选择器的第一个（默认）」而芯片不是那个电压）就在分组写 `model` / `rx_model`；「IBIS：…」开头的注意是绑定有问题（文件、器件名、脚名），照它改 part.toml 或 `[si.parts]` |
| `ibis` | 每个驱动模型的波形重算差在幅度 1 % 以内（好模型一般 0.1 % 以内）；「没读的」里有 `[Submodel]` / `[Driver Schedule]` / 封装模型时说明这部分没算 |
| `smps` | 每路电源「合格」，最后一行「没有超的」；「算不了」照它说的看（多半是两个脚之间没有铜连着）；「自动认的」电源先用 `--suggest` 核对器件、网络、回路对不对 |
| `drc` | 「间距违规 0，离板边太近 0，压禁布区 0，没连通的网络 0」、「悬空线头 / 过孔：0」、「铺铜填充：0 处比规则近」，没有「孔到孔」那行，最后一行「全部通过」 |
| `pour` | 「自检（照间距表，不留余量）：0 处比规则近」 |
| `constraints` | 「按嘉立创 DRC 口径检查：差分对线宽 0、差分对间距 0、对内长度差 0、等长误差 0」（导入的老板子常有长度差、等长误差：那是原设计，照实告诉用户） |

### 不成功时

- `gen` 报错：照报错改设计文件。「unknown footprint X」：不是标准名、也没定义，`footprint list` 看有哪些，或者写一个 `[[footprints]]`。「U1: group "" is not one of the blocks」是器件没写 `group` 或块没定义；「block X: no room left in its regions for R5」是功能块的自动排位区放不下，把 `regions` 放大或给器件 `pcb` 位置。
- `check` 有逐脚差异：多半是脚号和焊盘号没对上（封装少了这个号，或符号脚号写错）。有「重叠」「伸出板外」：挪 `pcb` 位置；故意伸出板边的连接器写进规则文件 `[check] allow_outside`。
- `erc` 报「引脚悬空」：设计文件里这个脚没接网络。对着数据手册看：写着 NC / DNC / 保留不接的、没用到的 IO、连接器空位，列给用户确认后写进这个器件的 `nc = [脚号, …]`（原理图上画非连接标识，`erc` 就不报）；不该空着的补上网络。「一组导线多个网络名」「网络标识和导线名不一致」：一根线上标了不同的名字，嘉立创按名字连网络，会把两个网络并成一个。「引脚和焊盘对不上」：符号脚号和封装焊盘号不一一对应，同 `check` 的逐脚差异一样查。
- `route` 没布通：器件摆得太挤或挡了通道。挪器件、给关键网络写 `[nets] first`（先布）或 `priority`；别乱改网格、间距这类参数。
- 看到很多短线：先区分焊盘到过孔、接铺铜的正常出线和多余短桩，分层看它后面是否还有连接。布线器会清理悬空端、被同网同层另一段完全覆盖的线段；差分扇出和等长补偿都去掉相邻重复坐标造成的零长度线。锁定线、`keep` 网络和 `only` 没选中的网络保留。不要只按长度删线。用 `drc --clearance 0.152` 单独看「悬空线头 / 过孔」，再用不带 `--clearance` 的 `drc` 检查工程规则；悬空 0 不代表所有网络都接通。
- `drc` 间距违规：看两边是谁（位号、网络、坐标），多半是器件太近或封装焊盘画错；改设计文件重来。
- `hookup` 报错误：照报出的脚和规格书出处（方括号里）去看，多半是脚接错了（两个脚对调、电源脚接错网、该有的电感 / 电容不在那两个脚之间）；规则本身也可能写错，对着规格书那一页确认，是规则错了就改库里的规则，请用户审。
- 电气对不对（引脚功能、器件选型、极性）：元件库里写了接法规则的芯片 `hookup` 查；没写规则的工具查不出来，出 `pdf` 或 `render --view sch` 让用户看原理图，引脚按数据手册核，或者先给这颗芯片写规则（见下一节）。

## 做库里的新元件（公司元件库 PartsLib）

库是 git 仓库（默认本机 `lib link` 过的那个；`lib status` 看是哪个、有没有没提交的改动）。`lib new`、`lib build`、`lib assign` 会写库里的文件：跑之前看有没有别人没提交的改动，做完请用户审过再提交。**料号由用户定，别编**；立创编号查到了才写。

0. 先找库里有没有：`lib search <型号>`、`lib search --lcsc C…`；要的是某种功能的件（带 USB 的 MCU、某个封装的 LDO）就 `lib search --pin USB_DP --status released`、`lib search LDO --footprint "SOT-23*"`、`lib search --category IC/电源/LDO`（库根目录有分类表 `categories.csv` 时），能用现成的就别新建。
1. `lib new <型号> --manufacturer <厂家> --package bga|soic|sop|qfp|son|qfn [--pins N] [--lcsc C…]`。
2. 读数据手册填三样（每一个数、每一个脚名都要有出处，拿不准的写进 part.toml 的 `notes`，别猜）：
   - **引脚表** `symbols/<型号>.pins.csv`：数据手册的引脚表逐行抄（PDF 表格可以用 PyMuPDF 按字符坐标抠，它自带的表格取字会把下划线挪位，别直接用）。大芯片至少两处互相核对：引脚号列表对球位图、功能表、电源 / 地分组表，数目和名字都对上再用。type 按功能表的方向（GPIO 写 io，模拟脚写 analog，电源 power，地 ground，用途不明的写 nc 并在 description 说明）；unit 按功能分（DDR、各组 GPIO、音频、电源、地……，参考原厂参考原理图的分法）；side：地址 / 控制、输入放左，数据、输出放右；group 把同一组的脚排在一起。
   - **封装** `footprints/<型号>.toml`：抄封装尺寸表的最小 / 标称 / 最大（D、E、A、A1、b、e、L，BGA 还有行列数和缺球位置）；数据手册注里有植球前球径写 `ball_nominal`；有推荐焊盘图时写 `pad`、`pad_span` 或 `land`。缺球位置对着底视图核一遍。
   - **part.toml**：描述、分类、数据手册链接、厂家型号，`notes` 写待核对的事。库根目录有 `categories.csv`（分类表）时，`category` 写表里的一个路径（比如 `IC/电源/LDO`）；表里没有合适的就问用户，别自己往表里加，不然提交审核会被拦。
3. `lib build <型号>`：看输出——符号每个单元几个脚、电源 / 地每个名字几个脚（和数据手册的电源分组表对）；封装的 IPC 计算过程、焊盘边到边；最后的检查「符号 N 脚和封装 N 个焊盘一一对上」、没有错误。再看 `preview/<型号>/` 里的图（能看图就看：符号每个单元、封装、3D）。
4. 立创有这颗料（先查立创编号）：`lib compare <型号> --lcsc C… --model`。球号 / 焊盘位置对不上是大事，逐个查清楚是谁错了；脚名截短、焊盘大小差一点是做法不同，照实告诉用户。
5. 结果告诉用户：生成了哪些文件、检查结果、和立创的差异、`notes` 里待核对的事；用户审过后再帮着提交到库（`git add` 逐个文件，别 `-A`）。
6. **接法规则**（芯片值得写的：电源芯片、收发器、带外部元件的模拟芯片）：在符号文件里加 `[hookup]`（格式见 PartsLib README，例子 `symbols/NCN5130.toml`）。**只照数据手册写，别照手上的设计写**——典型应用图逐脚看每个脚接什么（看清导线交叉处有没有点、跳线），外部元件表抄取值范围和额定电压，功能说明里「不用时接 X」写成几选一的 option；每条写出处（页、图、表）。写完：拿一个确认接对的工程跑 `hookup` 要全对，再把一个脚故意改错（两脚对调、电源脚换网）要报出来；然后请用户对着规格书核这张规则表。

**用户给的是 PADS 元件库**：要的是 PADS Library Manager 导出的 ASCII（第一行 `*PADS-LIBRARY-PART-TYPES-V9*` / `…-SCH-DECALS-V9*` / `…-PCB-DECALS-V9*`，扩展名 .p / .c / .d；二进制的 .pt9 / .pd9 / .ld9 请用户在 PADS 里选库 → Export 成 ASCII，三种都导出）。先在临时文件夹 `easyedatool lib --lib <临时库> import <文件夹> --preview` 看报告和预览图，没问题再导进真库。看报告：「读不懂的一行」「没导入」的器件类型、按名字猜的脚长（请用户把公共库的引脚图形一起导出就不用猜）都照实转告；导进来的都是草稿，料号、厂家型号请用户补。

## 别的常见活

- **看 EDA 里手画的板**：`info` → `check` → `drc`（不带规则文件就按工程里 EDA 的间距规则查、不查隔离带）→ `render --view layers`。
- **出下单文件**：先 `drc`，再 `fab <工程> -o <文件夹>`（里面的 zip 直接传嘉立创）、`bom`、`pdf`。工程里有铺铜没填充时 `fab` 当场算好（会提示）。
- **铺铜**：`gen`、`route` 已经自动算。用户在 EDA 里改过走线：`pour <工程>` 看和存的差多少，`pour <工程> --write` 写回（守规矩 1、4）。
- **板子布好了，只重画原理图**：`easyedatool gen 设计 --out <工程> --schematic-only`（加 `--layout pages`）。只换原理图，PCB 一个字节不动，器件沿用板子上的 Unique ID 和封装 id；跑完 `check` 要「逐脚差异 0」。用户开着 EDA 的话先请用户关掉这个工程。
- **让用户看着你画**：用户说想看、想盯进度，或者要跑 `route` 这种几十秒的活：先 `easyedatool view <工程>`（输出「预览窗口打开了」），再照常跑命令，不用另做什么。窗口不点「开始改」时只读文件，不用像 EDA 那样先关页面；同一个工程已经开着窗口就别再开。找不到窗口程序时（报「找不到预览窗口程序」）照常干活，告诉用户可以装 Flutter 编 `viewer/`。
- **用户想自己改**：告诉用户在预览窗口里点「开始改」。PCB 上：点器件选中，拖着挪，R 转 90°，B 翻到另一面，L 锁定。原理图页上：点引脚改接到的网络、断开、打 ×，点器件改值、删掉，点导线给网络改名，「加器件」加阻容感、LED、测试点或元件库的件（gen 生成的工程才能改原理图）。Ctrl+Z 撤销，改完点「改完了，交给 AI」。人改的时候别跑改工程的命令（规矩 10）。
- **处理审核意见**（`easyedatool review <工程>` 输出「审核意见：要处理的 N 条」，下面每条是「#编号 位号：意见」；edits.log 末尾也会列出）：一条条照意见改（改设计文件再 `gen`，改板子再 `route` / `pour --write` 等），改完一条就 `easyedatool review <工程> --answer <编号> "怎么改的"`（一句话说清改了什么，如「新加 R2 100k 上拉，U1.3 改接 EN」），输出「第 N 条意见（…）记下了回复」才算回复上；用户在窗口里确认或退回（退回的那条又出现在「要处理的」里，再看一遍意见）。意见看不懂或觉得不该改，就问用户，别乱改，也别不回复。输出里「审过以后又改了、勾已经不算的」是用户审过、后来又变了的器件，用户要重看，不用你做什么；用户审过的器件（`--json` 的 `ok`）没必要别动。
- **人在窗口里改过以后接着干**（工程里有 `.easyedatool/edits.log`，设计文件旁边有 `<设计>.layout.toml`）：先读 edits.log 看人改了什么。「原理图第 N 页 …」几行是人拖、转、画的（画法记在布局文件的 [sch] 里，不用管）。有「设计文件：加了禁布区 …」时，人在窗口里画了禁布框（写进了设计文件的 `[[regions]]`）：布线器不读设计文件的禁布区，接着 `route` 之前在规则文件里加一个一样的 `[[keepout]]`（同样的矩形和层）。gen 的输出有「注意：上次生成以后，原理图 … 在外面（嘉立创里？）改过」时，用户在嘉立创里改过那几页，这次生成照设计文件重写、改动没了：告诉用户，问要不要从 git 里找回来对着改设计文件。有「人从窗口跑了 route…」这类行时，人在窗口菜单里跑了改板子的命令（布线、重布某个网络、差分、等长、加粗）：板子以现在的为准，别把它改回去。有「窗口里退回到 … 那一版」一行时，用户把工程、设计文件、布局文件退回了那一版（git 里存成了新的一版）：从退回后的样子接着干，别把退掉的改动又做回去，除非用户说要。「设计文件：…」那几行是人在原理图上改的连接（画线、删线、加标签也算）、值、增删的器件，已经直接改在设计文件里了（`git diff` 设计文件也能看到）：以它为准接着改，别按你原来的打算把它改回去；觉得人改得不对就问用户。设计文件开头写着是脚本生成的（`# Generated by …`，edits.log 里有「注意：设计文件是脚本生成的」）时，先把这些改动搬进生成它的脚本，再重跑脚本，不然改动就冲掉了。再 `gen` 时器件留在人摆的位置、布好的线写回去（输出里有「布局文件 …：照它摆 N 个器件」「布局文件里的走线 N 段、过孔 M 个写回了工程」），新加的器件自动排进空地；别删布局文件（删了就回到自动摆法，人摆的全没了），也别手改它。要挪某个器件：改设计文件里它的 `pcb` / `angle` / `side`（改了的那个以设计文件为准，输出里列在「设计文件改了位置的按设计文件摆」），或者请用户在窗口里挪。人挪过器件后原来连着的线对不上（飞线和 `drc` 的「没连上」会显示）：补线用 `route` 时在规则文件 `[nets]` 写 `keep = ["*"]`，留住已布的线、只布没连上的；不写 keep 会把全部走线删了重布。`easyedatool layout <工程>` 看布局文件和工程是否一致。人在窗口里拖过原理图（`layout` 的输出有「原理图：照布局文件里记的画法画」）：再 `gen` 时原理图照人画的画，不再自动排版；你在设计文件里的改动 gen 自己对上去（删掉的器件连线去掉，新器件放进它那一块附近的空地，引脚换了网络就断开、补上标签，网络改名就改标签），输出里「原理图照布局文件里记下的画法画」下面列出改了什么；出现「原理图和设计文件还有 N 处对不上」就是没对完，跑 `check` 看是哪些引脚，告诉用户。新器件放的位置不好看，请用户在窗口里挪；别为了重新排版去跑 `layout --forget-sch`（人画的全没了），要的话先问用户。
- **把 PADS 板子搬进嘉立创**：ASCII `.asc` 第一行是 `!PADS-…`，先 `info` 看「走线两端落在焊盘上：… 对不上 0 处」。原生二进制 `.pcb` 可以 `easyedatool import 板子.pcb --out <空文件夹>`：Windows 调用本机已安装、已授权的 PADS Layout，把私有副本导出为完整 ASCII 后转换，不改源文件。已有 PADS 进程时会拒绝接管，保护未保存文档；这时在现有 PADS 手动 File → Export 完整 `.asc`，再导入。未安装 PADS 或非 Windows 系统也用 `.asc`。导出失败或超时不能说已读全，不要关闭别人的 PADS 或使用 Application.Quit。导入后看焊盘「位置不对 / 形状大小或开窗不对 / 孔不对 / 网络不对 / 缺的」均0、过孔和铺铜填充数相等、每层走线长度一致，才算转对。「注意」照实转告；给 `--sch 原理图.DSN` 可合并同版OrCAD原理图，只有一边的器件、逐脚网络差异仍须报告。原生 `.pcb` 先 import，再对生成的工程 info / render / view。METRIC导出可混用I（mil）和M（毫米）封装，BASIC已归一化；发现巨大焊盘或端点偏移先检查单位，不能直接缩放最终工程凑图。提醒：嘉立创重建铺铜会按嘉立创规则重算。
- **查 Altium 板子**（`.PcbDoc`，二进制的和文本格式 `|RECORD=…` 的都认）：`info 板子.PcbDoc` 看读了哪些、「没读」的照实转告；`drc`、`render`、`kicad`、`fab`、`view` 直接用。查安规（电气间隙、爬电）时规则文件按电路分网络类（AC 保险前 / 保险后 / N、DC 初级、次级……），类对类写公司安规表的数（加生产余量），要和 KiCad 对数就加 `[drc] creepage_style = "kicad"`，再 `kicad 板子.PcbDoc --rules 规则.toml --drc` 让 KiCad 跑一遍；两边不一样时先看是不是碰到圆弧走线（KiCad 自己导入 Altium 时圆弧是真圆弧，它的爬电不拿圆弧挡路、还会算出比直线间隙短的数）。
- **把 Altium 板子搬进嘉立创**：`easyedatool import 板.PcbDoc --sch 同一版的图.SchDoc --out <空文件夹>`。看自检：器件、焊盘（位置 / 形状 / 网络 / 缺的）、过孔、走线长度、铜皮面积都对上，原理图「连接自检」断开和短路是 0，「原理图和 PCB 配对」只在一边的器件、「逐脚比」网络不一样的地方照实告诉用户（常见的是不贴件、改版后改过的网络）；「同名封装画得不一样的拆成了几种」也转告。只有 PCB 时去掉 `--sch`。
- **把 Altium 原理图搬进嘉立创**：`easyedatool altium 图.SchDoc` 先看摘要（「没画的」「注意」照实转告：端口画成图形、贴着引脚的电源端口补了短线这些），再 `--out <空文件夹>`，看「连接自检」要「断开的网络 0，短到一起的 0」。有同一版的 PcbDoc 时用 `--netlist` 出网表，和 PCB 的焊盘网络对一下（网络名大小写可能不同：Altium 的 PCB 会改成大写）。一次一张 SchDoc，层次图还没做。
- **把 OrCAD 原理图搬进嘉立创**（原厂参考设计、老图纸）：`easyedatool orcad X.DSN` 先看摘要（「读不了的：0 处」才算读全，新格式和 16.2 老格式都认；报「no pages to import」说明给的是库文件或读不懂的版本，把摘要原样告诉用户）→ `easyedatool orcad X.DSN --out <空文件夹>`（文件夹名就是工程名，嘉立创按文件夹名认工程，别另给不一样的 `--name`）。看输出的「连接自检」：「断开的网络 0，短到一起的 0」才算对；「注意」里的重复位号、符号改过的器件、隐藏电源脚照实转告用户。再 `render <工程> --view sch` 出图看，用户手上有 OrCAD 导出的 PDF 就对着看。
- **查功率器件发热、走线载流**（开关电源、大功率驱动板）：在规则文件里写 `[thermal]`（格式见 `references/rules-format.md`）。器件参数照数据手册抄（常用件放进元件库 part.toml 的 `[thermal]`，以后不用再抄），工况（电流有效值、开关频率、关断电压电流……）问用户或按电路算，**别编**，估的数在结果里照实说是估的。大电流网络写 `from` / `to`（电流从哪个脚进、哪个脚出），工具把走线、过孔、铺铜当电阻网解出每段电流；只给电流的网络是按整网电流的保守估算。看结果：器件「超」的看是哪项损耗大（导通 / 开关 / Coss）和热阻怎么取的；网络「超」的照报出的位置加宽走线、加铜、多打过孔，改完再跑。要看整块板哪里热、器件挤在一起互相加热多少：加 `--map 热分布.png`（能看图就看图；预览窗口开着时温度直接叠在板上），器件有 ψJB 的写 `psi_jb` 才有板温 + ψJB 的结温；板面换热系数默认静止空气，装在密闭小壳里、有风扇的要问用户再改 `h_top` / `h_bottom`，结果照实说是估算。
- **查开关电源的版图**（DC-DC、PMIC、反激）：先 `easyedatool smps <工程> --suggest --png 电源.png`。看认出来的每路电源（芯片、电感、开关节点、回路里的电容）对不对，不对就把 `--suggest` 打出来的那段贴进规则文件的 `[smps]` 改，再加 `--rules` 跑。看结果：热回路「超」的看那几段——「绕远了：直线只有 x mm，中间隔着 …」说的就是挡住回流的铜（顶层被开关节点隔开、底层的地被别的线切开），建议把输入电容挪到芯片的 VIN 和 GND 脚边上、地平面别让走线切断；开关节点「过孔 / 多层」的能不跨层就不跨；安静网络挨太近的把 FB 走线挪开或换到隔着地平面的层；去耦不合格的就近加电容或把地打到最近的地平面。能看图就看 `电源.png` 和每路的放大图。数值是版图几何，不是仿真，照实说。
- **查高速线的反射和串扰**（DDR、SDIO / eMMC、SPI、时钟……）：先 `easyedatool impedance <工程>` 看叠层像不像真的（导入的板子常是默认叠层：每层介质一样厚）。问用户要板厂的叠层单（叠层阻抗表），照抄进规则文件 `[stackup]`；介电常数没写就拿阻抗表的一行反推（`impedance --stackup 规则.toml --layer 1 --field --width …` 对上它的阻抗）。驱动参数照芯片手册（上升时间、驱动强度 / 输出阻抗、片内端接、脚电容；差分接口的接收端差分端接写 `r_diff`，比如 MIPI / LVDS 100 Ω，USB 高速每根 45 Ω 写 `odt`），按网络分组写进规则文件 `[[si.group]]`（格式见 `references/rules-format.md`），没有就照实说用的是通用值。跑 `easyedatool si <工程> --rules 规则.toml --xtalk --png 波形.png`，看驱动脚对不对（输出里写了按什么定的），能看图就看图。过冲超的：加串联电阻（驱动端）或端接、减小线长 / 残桩、让阻抗连续（看「阻抗和主体差 15 % 以上的段」）；串扰超的：拉开间距（3 倍线宽以上）、缩短并排长度、换到带状线层、中间加地。用户要核对仿真本身时加 `--spice 文件夹` 再跑 `python tools/verify_si/compare.py 文件夹`（要装 KiCad）。没有 IBIS 时结果是线性通用模型、无损线，照实说。
- **用 IBIS 仿真**：芯片厂给的 .ibs 先 `easyedatool ibis 文件.ibs` 看器件名、脚、模型、波形重算差（> 1 % 先别用）。绑进元件库：文件放 `<库>/sim/<型号>/`，part.toml 加 `[sim] ibis = "sim/<型号>/x.ibs"`、`ibis_component = "<[Component] 名>"`（封装焊盘号和 IBIS 脚名不一样时 `[sim.ibis_pins]` 焊盘 = 脚名），`easyedatool lib check <件>` 看「IBIS …：[Component] …，N 个信号脚有模型」和焊盘对不对得上。板子上的器件要能认回库里的件（gen 用库件生成的自带料号 / Manufacturer Part / 立创编号属性；别的板子没有就在规则 `[si.parts.U1] part = "料号"` 或直接 `ibis = "文件"`）。`si` 自动找库（`--lib`、环境变量、工程旁边的 `easyedatool.toml`）。DDR 这类 I/O 脚：驱动强度写分组 `model`，片内端接（ODT）写 `rx_model`（都是 IBIS 里 `[Model Selector]` 的模型名）。IBIS 文件一般有保密协议：放公司元件库，不进别的仓库。
- **找某个器件 / 网络**：`pads --part U3`；`render --view layers --net SPI_MOSI --window x0,y0,x1,y1 --ppmm 60`。

## 别做

- 窗口“改线宽”支持一次选择多段，写前整批检查铜间距、孔、连通、约束和新增工艺错误；报错后没有任何一段写入。工程之外的规则文件仍须再跑 `drc --rules`。遇到焊盘或邻网过孔卡住电源线时，先试安全改道或移动过孔并复查原网连通，不要把被拒绝的加宽拆成局部细长鼓包。

- 连续主干改道会逐候选检查项目的短鼓包、细颈等质量规则，拒绝后再找其他路径或较小目标宽度；最终整板检查仍须通过。通过编辑接口回放推挤时，`moved.old` 必须是预览时完整原线段，网络、层、线宽和两端点都要一致。报「原线段已改变，请重新预览」时重新读取板子再规划，不用中点或邻近线段替代；锁定原线和无法唯一定位的重叠线不允许替换。

- 别手改 `.epcb2` / `.esch2` 里的记录（ticket、删除记录、铺铜填充这些规矩很多）：改设计文件重新 `gen`，或者让用户在 EDA 里改。真要改：二进制读写、保持 LF（规矩 9），改完 `check`。
- 别把 `drc --clearance 0.152` 的结果当成 EDA 的结论：那是所有铜皮一个间距（旧脚本 drc.py 的做法）；不带它才按工程里 EDA 的规则表。
- `pair` 默认在指定层布耦合段，顶层细间距端可经错开的过孔到底层；每根网络须有两个端点，经过串阻、ESD 的用 `--ends A,B` 分段。成品密板上重布可能布不通，别硬改规则凑。写回前先 `pair` 不带 `--write` 看报告。
- `tune --write` 之后提醒用户在嘉立创里重建铺铜（新走线压着旧填充，嘉立创 DRC 会报 Copper Region(Filled) to Track）；「还差」的网络是直线段上放不下，照实告诉用户，别硬塞。
- 阻抗先看叠层对不对：`impedance` 第一段是工程里的叠层，导入的 PADS 板常是占位值（每层一样厚），那样算出来的阻抗没意义，先请用户在嘉立创层管理器里设成实际叠层，或用 `--stackup` 选立创标准叠层。嘉立创的计算器对「上下介电常数不一样」的内层（立创标准多层叠层的内层都是）、线距小于 5 倍铜厚的差分带状线算不出来，这些用 `--field` 的场求解结果；它的耦合微带公式比场求解高约 5%，用户要准的线宽时给场求解的数，要和嘉立创界面一致时给嘉立创的数，两个都说清楚是哪个。
- 别用桥（`overwriteNetRules`）或手改 `RULE_SELECTOR` 给差分对 / 等长组指定规则：规则要同时写在对、组和它们每根网络的指定上嘉立创才按它查（见 `references/eda.md`）。用 `constraints --from 约束.toml --write`（格式见 README「差分对和等长」）。
- 网格铺铜（EDA 里设成网格的）不算，留着工程里存的。
- 别拿 `render` 的图代替 `check` / `drc`：看图看不出差 0.01 mm 的间距和接错的脚。

整板布线时：`pair --no-tune` 先布差分主干 → `route` 用 `[nets] keep` 保留差分网络并完成普通连接 → `tune --group` / `tune --pair` 补等长 → `pour --write` → `constraints` 和 `drc`。不要在普通引脚还没有出路时先塞入蛇形线；它可能占掉相邻电源、控制脚的过孔位置。

## 快速自测（第一次用、或怀疑环境有问题时）

完整的 STM32MP157 复杂示例可用 `python examples/build_mp157.py --tool bin/easyedatool.exe --out MP157Demo --export` 恢复，不必从头布线。AM319 屏的原始 PDF、30 针接法及 1 脚方向在 `examples/docs/display/`；构建脚本还会核对一线 DSI 和计入封装长度差后的配对长度。实物驱动与点屏状态以例子 README 为准。

在一个临时文件夹里跑（`<目录>` 换成真实路径，`examples/` 在本目录下）：

```
easyedatool gen examples/demo.toml --out <目录>/Demo
easyedatool check <目录>/Demo
easyedatool route <目录>/Demo --rules examples/demo.rules.toml
easyedatool drc <目录>/Demo --rules examples/demo.rules.toml
```

应当：`gen` 「原理图 1 页：出图框 0，压标题栏 0，重叠 0」、「铺铜 2 块算好填充写进工程」；`check` 「全部通过」；`route` 「连接 5，布通 5，没布通 0」；`drc` 「全部通过」。

布线输出含「搜索步数用完」时，先查出线和元件摆放，再考虑在规则文件顶层加 `search_budget_scale = 8`（仍不够可用 `16`）。默认 `1`，`0` / `1` 保持原有预算；这个通用参数只增加搜索上限，不放宽间距、线宽或过孔要求。重布只在副本上做，已有线要留时设 `[nets] keep = ["*"]`；布完必须用正式规则查全板 DRC，不能把搜索命令退出码 0 当作已布通。
