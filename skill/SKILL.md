# easyedatool：嘉立创EDA工程离线工具

画板不用操作 EDA 客户端：写一个**设计文件**（器件、网络、位置），工具生成原理图和 PCB、布线、铺铜、检查，结果都是文字报告。

- 程序：`easyedatool` 在 PATH 里（apt / Homebrew 装好就是这样）。Windows 的 zip 里则是本目录下 `bin/easyedatool.exe`。下文的 `easyedatool` 都指它。
- 这个目录是说明书，不含源码。
- 参数全集：每个命令加 `--help`（中文）；汇总在 `references/commands.md`。
- 写设计文件：`references/design-format.md`，照 `examples/mp157demo.toml` 改（STM32MP157，100 × 80 mm，四层）。
- 布线 / DRC / 核对规则文件：`references/rules-format.md`，例子 `examples/mp157demo.rules.toml`。差分对在 `examples/mp157demo.constraints.toml`。
- 用户同时开着 EDA 客户端：`references/eda.md`。
- 给人看的说明：仓库里的 `README.md`（中文）和 `README.en.md`。

## 规矩（先读）

1. **会改写工程的只有七个**：`gen --out`（sch/、pcb/ 整个换掉，索引就地覆盖）、`route`（删掉**全部**走线、过孔、铺铜填充重新布）、`pour --write`（换掉铺铜填充）、`constraints --write`（只改网络记录上的差分对 / 等长组 / 网络类字段、这两类规则和规则指定，索引版本号）、`tune --write`（把要绕的直线段换成蛇形线，索引版本号）、`pair --write`（这对原来的走线过孔换成新布的，索引版本号）、`repair`（只改换行、BOM、索引版本号，删空临时文件）。跑之前看工程在不在 git 里、有没有没提交的改动，有就先问用户要不要提交；改坏了用 git 回滚。用户的规矩：**就地改原工程，用 git 提交和回滚，不要复制出 V0.2 这样的新目录**。
2. `route` 只用在生成的板子上，或者用户明确要全板重布：手画的板子一跑，手工走线全没了。
3. 其余命令都只读：`info`、`pads`、`render`、`check`、`erc`、`drc`、`pour`（不带 `--write`）、`constraints`（不带 `--write`）、`impedance`、`tune`、`pair`（不带 `--write`）、`pdf`、`netlist`、`bom`、`fab`（只写到 `-o` 给的地方）。`lib` 不碰工程，只写元件库（见「做库里的新元件」）。
4. 用户的 EDA 客户端开着这个工程时：**先让 EDA 关掉要改的页面（PCB 页），再跑写文件的命令，跑完再打开**，否则 EDA 看不到新内容，还可能把内存里的旧版本存回去。细节见 `references/eda.md`。
5. `drc`、`check`、`erc` 查出问题时退出码是 1：那是检查结果，不是程序出错，读输出改问题。
6. 路径：工程文件夹、`.eprj3` 或 `.epcb2` 都能当输入，中文路径没问题；Git Bash 里用正斜杠或加引号。
7. PCB 坐标一律毫米、y 向上（和 EDA 界面一致）；原理图里自建符号的引脚坐标是 EDA 图纸单位（10 mil）。
8. 判断对不对**看文字输出**（下面「怎么算成功」），PNG 是给人看的；能看图的话再用 `render` 出图核对。
9. **在 Windows 上别用文本方式写工程文件**（Python `open(f, "w")` / `write_text`、PowerShell `Set-Content` / `Out-File`、记事本另存）：会写成 CRLF 换行或加 BOM，嘉立创整个文件读不了，PCB / 原理图打开是空的，关工程时还会删掉索引里的版本号。非改不可时二进制读写、保持 LF，改完跑 `easyedatool check <工程>`，「工程文件」那行要是「没问题」。用户说「嘉立创打开 PCB 没了 / 原理图是空的」，先跑 `check`，报 CRLF 之类的错误就请用户在 EDA 里关掉这个工程，再 `easyedatool repair <工程>`，然后请用户重新打开。
10. **AI 和人轮流改**：用户在预览窗口里点了「开始改」时，改工程的命令（`gen`、`route`、`repair`，带 `--write` 的 `pour` / `place` / `tune` / `pair` / `widen` / `constraints`，`layout --save`）报「预览窗口里有人在改这个工程（… 开始，…）」就不跑——这不是出错：停下来告诉用户，等用户在窗口里点「改完了，交给 AI」再接着干，别反复重试，也别绕过去直接改文件。接着干之前先读工程里的 `.easyedatool/edits.log`（人挪了、转了、翻面、锁定了哪些器件），照它调整下一步（见「别的常见活」的「人在窗口里改过以后接着干」）。每一轮开始也跑一次 `easyedatool review <工程>`：用户在窗口里写的审核意见在那里（见「别的常见活」的「处理审核意见」）。

| `footprint` | 画封装 / 量封装：标准名或设计文件里的封装，打印量出来的脚间距、两排中心距、焊盘表、设计文件写法，`-o` 出预览图 | `easyedatool footprint list`、`easyedatool footprint SOIC-8`、`easyedatool footprint 设计.toml --name QFN32 -o 看.png` |

| `repair` | 修工程文件：CRLF 换行改成 LF、去掉 BOM、补回索引里丢掉的版本号、删掉空临时文件（别的一个字节不动） | `easyedatool repair <工程>`（先请用户在 EDA 里关掉这个工程） |

| `drc` | 间距（按工程里 EDA 的规则表）、板边、禁布区、断网、悬空、隔离带、铺铜填充 | `easyedatool drc <工程> --rules 规则.toml` |
| `hookup` | 接法检查：照元件库里芯片的接法规则（按数据手册写）查原理图——两脚之间的电感 / 电阻 / 电容和取值、额定电压，该同网 / 接地 / 不接的脚，用的是数据手册哪种接法；查得出接错脚这类 ERC 查不出来的错 | `easyedatool hookup <工程> [--lib <元件库>]` |
| `thermal` | 损耗结温和载流温升：照规则文件 `[thermal]` 的工况算功率器件损耗、结温（θJA / 散热器 / 按散热焊盘铜面积插值）、额定值用到多少；走线、铺铜、过孔按 IPC-2152 算温升，给了电流从哪进、从哪出（from / to）解出每段电流和压降（铺铜细分成网格）；`--map` 再算整块板的温度分布，出热分布图（器件互相加热、焊盘下的板温，给了 ψJB 算结温） | `easyedatool thermal <工程> --rules 规则.toml [--json 热.json] [--map 热分布.png]` |
| `smps` | 开关电源版图检查：热回路（沿实际铜走的三维回路面积、估电感，某段绕远了说直线多远、中间隔着哪些网络）、开关节点的铜和过孔、FB / COMP / SS 这类安静网络离开关节点多远 / 相邻层压着 / 从电感底下走、芯片每个电源脚的去耦（铜路径和回路面积）；不写规则自动认降压 / 升压 / 多路 PMIC / 反激（有原理图按引脚名），`--suggest` 按规则文件写法打出来 | `easyedatool smps <工程> [--rules 规则.toml] [--png 电源.png] [--suggest]` |
| `si` | 信号完整性：网络（连同串联电阻 / 电容连过去的网络）按叠层用场求解器算每段 Z0 和延时，加过孔、端接搭成电路做时域仿真；反射报每个接收端的飞行时间、过冲、回沟、稳定时间、单调性；`--xtalk` 串扰（同层平行的网络，场求解器算耦合，报近端 / 远端）；差分对（按名字认，两根反相一起驱动、并排段按耦合线、`--rdiff` 差分端接）报差分波形、P/N 偏斜、共模、差分阻抗；元件库里绑了 IBIS 的器件（part.toml `[sim] ibis`，或规则 `[si.parts]`）自动按 IBIS 算：非线性缓冲器、封装，选择器按电源脚网络名的电压挑模型，上升 / 下降两个沿按伏特报、查接收端 Vinh / Vinl 余量；没有 IBIS 的按通用模型（上升时间、输出阻抗、脚电容），规则文件 `[si]` / `[[si.group]]` 按网络分组写；`--png` 波形图，`--spice` 导出给 ngspice 复算 | `easyedatool si <工程> --net "LPDDR4_DQ*" [--rules 规则.toml] [--lib 元件库] [--xtalk] [--png 波形.png]` |
| `ibis` | 读 IBIS 文件：器件、引脚、模型选择器、模型（类型、电源、C_comp、门限、有哪些表）；每个驱动模型的 V–T 波形放回夹具重算对表（差超过幅度 10 % 退出码 1） | `easyedatool ibis 模型.ibs [--component 器件] [--model 模型] [--corner typ]` |
| `erc` | 原理图电气规则，照嘉立创原理图 DRC 逐条查、级别照它：引脚悬空、导线没接引脚 / 只接一个引脚、一组导线多个网络名、网络标识和导线名不一致、引脚端点重叠、位号、缺封装、引脚和焊盘对不上、多部件、超出图纸、不在格点；`--pins` 再查引脚类型冲突 | `easyedatool erc <工程>` |
| `pair` | 差分对布线：按规则在一层上自动走，两根等距并排、两头从焊盘出线（BGA 缝里也能出），布完逐段精确查间距，长度差超了自动绕等长；布不通照实报（找不到路、出不来、要交叉） | `easyedatool pair <工程> --pair USBH --replace`、`--layer 2 --write` |
| `tune` | 绕等长：直线段上加蛇形线，差分对短的补到另一根、等长组超出的补到最长那根、一根网络补到指定长度；按工程间距规则找地方，放不下的照实报「还差多少」 | `easyedatool tune <工程> --all`、`--pair USBH --write`、`--net CLK --length 42.5` |
| `impedance` | 阻抗，照嘉立创阻抗计算器算（逐位一致）：叠层表、每层单端 / 差分要多宽、给定线宽的阻抗、每对差分线按实际走线的阻抗；`--field` 再用二维场求解器算（嘉立创算不了的内层也能算，更准）；`--stackup` 换成立创标准叠层 | `easyedatool impedance <工程> --zdiff 90 --gap 0.127 --field`、`--layer 1 --width 0.15 --gap 0.18`、`--stackup list` |
| `constraints` | 差分对、等长组、网络类：每对的规则、两根线长度和长度差，每组最长最短；按嘉立创 DRC 口径检查（差分对线宽、间距、对内长度差、等长误差，和嘉立创逐条一致）；`--auto` 按网络名认差分对并按已布走线量规则，`--from 约束.toml` 加约束，`--write` 写进工程 | `easyedatool constraints <工程> [--json 检查.json]`、`easyedatool constraints <工程> --from 约束.toml --write` |
| `render` | PNG：正面 / 背面实物、分层线路图（多层板带内层）、原理图每页一张；也认 PADS `.asc`、Altium `.PcbDoc` | `--view top\|bottom\|layers\|sch`、`--layer 16`（只画内层2：1 顶层、2 底层、15 内层1…）、`--window x0,y0,x1,y1 --ppmm 60`、`--net GND` |

## 画一块新板（最常用）

1. **写设计文件**：复制 `examples/mp157demo.toml`（STM32MP157），按 `references/design-format.md` 改。要点：
   - 板框 `[board] outline`，毫米。
   - 符号：芯片、连接器用自建符号（`[[symbols]]`，`left` / `right` 两列引脚）；电阻电容电感二极管 LED 测试点用内置的（`RES` `CAP` `IND` `DIODE` `LED` `TEST_POINT`）。
   - **封装按这个顺序选**：① 标准名直接写在器件的 `fp` 里（`easyedatool footprint list` 列出全部：`SOIC-8` `TSSOP-20` `SOT-23-6` `SOT-223` `LQFP-48` `R0805` `C1206` `HDR-2x5-2.54` `DIP-8`……，以及内置的 `R0603` `C0603` `R0402` `C0402` `L0402` `L0603` `LED0603` `SMA` `TP0.5`）；② 没有的，写一个 `package` 形式的 `[[footprints]]`，只填数据手册推荐焊盘图上的数（脚数、脚间距、两排中心距、焊盘长宽、本体），坐标工具算；③ 实在不规则的（连接器、模组）才手写每个焊盘的坐标。写法见 `references/design-format.md`。
   - 每个器件 `[[parts]]`：`ref` 位号、`sym` 符号、`fp` 封装、`value`、`nets = { 脚号 = "网络名" }`、`group` 功能块。**`group` 每个器件都要写，至少定义一个 `[[blocks]]`**（只有一个功能块也行）。
   - 位置：芯片、连接器、大器件给 `pcb = [x, y]`（封装原点在板上的位置，毫米）和 `angle`；小阻容可以不给，在功能块的 `regions` 里自动排。自动排的格子默认 0603 大小，大器件不给位置会叠在一起，要么给 `pcb`，要么写 `cell = [宽, 高]`。两种可以混用。
   - **符号的脚号必须和封装的焊盘号一一对应**（网络按号连到焊盘）。内置 `DIODE` 是 1 = 阴极 K、2 = 阳极 A；`LED` 反过来，1 = 阳极 A、2 = 阴极 K。
   - 接地铺铜 `[[pours]]`，禁布区 `[[regions]]`。
   - **封装最容易错，工具查不出它和真器件对不对**，照下面「封装检查单」做。
2. **生成**：`easyedatool gen 设计.toml --out <工程文件夹>`。设计文件写错会直接报错并说哪一项（未知符号、脚号不在符号上、位号重复……），改了再跑。
3. **核对**：`easyedatool check <工程文件夹>`，再 `easyedatool erc <工程文件夹>`（`gen` 跑完已经自动查过一遍 ERC）。
4. **规则文件**（布线用）：复制 `examples/mp157demo.rules.toml`，至少写 `[nets] pour`（铺铜网络）和 `power`（粗线网络），禁布区照设计文件再写一遍 `[[keepout]]`。差分对用 `examples/mp157demo.constraints.toml`。
5. **布线**：`easyedatool route <工程文件夹> --rules 规则.toml`。
6. **DRC**：`easyedatool drc <工程文件夹> --rules 规则.toml`。
7. **出文件**：`fab`、`bom`、`pdf`；要看图用 `render`。

改了电路就改设计文件、从第 2 步重来（`gen` 会清掉布线）。设计文件里写了 `[project] time` 的话，同一份设计每次生成的文件一模一样，git diff 只显示真改动。

### 封装检查单

1. 能用标准名就用标准名，但标准名是**典型值**：跑 `easyedatool footprint <标准名>` 看它量出来的脚间距、两排中心距、焊盘大小，和这颗器件数据手册的推荐焊盘图对一遍，不一样就写 `package` 形式的 `[[footprints]]`（同名会盖过标准名）。
2. `package` 形式：数字全抄数据手册的推荐焊盘图（land pattern / recommended footprint），不要凭印象估。`span` 是两排**焊盘中心**的距离（手册常给外沿或内侧距离：中心距 = 外沿 − 焊盘长 = 内侧 + 焊盘长）。
3. 手写焊盘（不规则封装）：原点放本体中心，焊盘坐标是焊盘中心，y 向上，负数正常；`outline` 是本体轮廓（也画成丝印框），焊盘可以伸出去，但一般压着它。
4. **每个自己写的封装都跑一遍** `easyedatool footprint <设计文件> --name <封装名>`：它从放好的焊盘量出脚间距、两排中心距、焊盘外沿，和数据手册的数一致才算对（不用自己算坐标）。
5. `gen` 输出「注意：封装 X：焊盘 … 没压着外形框」：手写的坐标或外形框多半写错了，按 3、4 查；SOT-223 这类引脚伸得远的封装本来就这样。

### 怎么算成功

| 步骤 | 输出里要看到 |
|---|---|
| `gen` | 第一行是工程路径和器件数；「原理图 N 页：出图框 0，压标题栏 0，重叠 0」；「铺铜 N 块算好填充写进工程」；没有「注意：封装 …」（有就按检查单核对）。「位号没地方放、藏起来了：…」只是提示 |
| `check` | 「网表 … 逐脚差异 0」，最后一行「全部通过」 |
| `erc` | 「致命错误 0、错误 0」，最后一行「全部通过」；「引脚悬空」的脚确认是故意不接的，写进设计文件的 `nc` 重新生成 |
| `hookup` | 每颗芯片「错误 0、警告 0」，最后一行「全部对上」；「接法：…」认出来的接法和设计意图一致（比如该用 DC2 却认成「不用 DC2」就是接错了）。「没写额定电压」是提示 |
| `route` | 「连接 N，布通 N，没布通 0」，后面没有问题清单 |
| `thermal` | 每个器件、每个网络「合格」，最后一行「全部在限值内」；「缺参数」照它说的补；「可能超」是没给 from / to、按整网电流算的，给了再看；规则文件里「没用上」的键多半拼错了 |
| `si` | 每根网络、每个接收端「合格」，串扰每根受害线「合格」，最后一行「没有超的」；「叠层：工程里没有……」或叠层是导入的默认值时绝对数不可信，先问用户要板厂叠层；「驱动 …（引脚最多的芯片）」方向不对就用 `--driver` / 分组的 `driver` 改；有 IBIS 时看每个脚「IBIS …：模型，…选的」：选的模型电压不对（「选择器的第一个（默认）」而芯片不是那个电压）就在分组写 `model` / `rx_model`；「IBIS：…」开头的注意是绑定有问题（文件、器件名、脚名），照它改 part.toml 或 `[si.parts]` |
| `ibis` | 每个驱动模型的波形重算差在幅度 1 % 以内（好模型一般 0.1 % 以内）；「没读的」里有 `[Submodel]` / `[Driver Schedule]` / 封装模型时说明这部分没算 |
| `smps` | 每路电源「合格」，最后一行「没有超的」；「算不了」照它说的看（多半是两个脚之间没有铜连着）；「自动认的」电源先用 `--suggest` 核对器件、网络、回路对不对 |
| `drc` | 「间距违规 0，离板边太近 0，压禁布区 0，没连通的网络 0」、「悬空线头 / 过孔：0」、「铺铜填充：0 处比规则近」，没有「孔到孔」那行，最后一行「全部通过」 |
| `pour` | 「自检（照间距表，不留余量）：0 处比规则近」 |
| `constraints` | 「按嘉立创 DRC 口径检查：差分对线宽 0、差分对间距 0、对内长度差 0、等长误差 0」（导入的老板子常有长度差、等长误差：那是原设计，照实告诉用户） |

### 不成功时

- `gen` 报错：照报错改设计文件。「unknown footprint X」：不是标准名、也没定义，`footprint list` 看有哪些，或者写一个 `[[footprints]]`。「U1: group "" is not one of the blocks」是器件没写 `group` 或块没定义；「block X: no room left in its regions for R5」是功能块的自动排位区放不下，把 `regions` 放大或给器件 `pcb` 位置。
- `check` 有逐脚差异：多半是脚号和焊盘号没对上（封装少了这个号，或符号脚号写错）。有「重叠」「伸出板外」：挪 `pcb` 位置；故意伸出板边的连接器写进规则文件 `[check] allow_outside`。
- `erc` 报「引脚悬空」：设计文件里这个脚没接网络。对着数据手册看：写着 NC / DNC / 保留不接的、没用到的 IO、连接器空位，列给用户确认后写进这个器件的 `nc = [脚号, …]`（原理图上画非连接标识，`erc` 就不报）；不该空着的补上网络。「一组导线多个网络名」「网络标识和导线名不一致」：一根线上标了不同的名字，嘉立创按名字连网络，会把两个网络并成一个。「引脚和焊盘对不上」：符号脚号和封装焊盘号不一一对应，同 `check` 的逐脚差异一样查。
- `route` 没布通：器件摆得太挤或挡了通道。挪器件、给关键网络写 `[nets] first`（先布）或 `priority`；别乱改网格、间距这类参数。
- `drc` 间距违规：看两边是谁（位号、网络、坐标），多半是器件太近或封装焊盘画错；改设计文件重来。
- `hookup` 报错误：照报出的脚和规格书出处（方括号里）去看，多半是脚接错了（两个脚对调、电源脚接错网、该有的电感 / 电容不在那两个脚之间）；规则本身也可能写错，对着规格书那一页确认，是规则错了就改库里的规则，请用户审。
- 电气对不对（引脚功能、器件选型、极性）：元件库里写了接法规则的芯片 `hookup` 查；没写规则的工具查不出来，出 `pdf` 或 `render --view sch` 让用户看原理图，引脚按数据手册核，或者先给这颗芯片写规则（见下一节）。

## 做库里的新元件（公司元件库 PartsLib）

库是 git 仓库（默认本机 `lib link` 过的那个；`lib status` 看是哪个、有没有没提交的改动）。`lib new`、`lib build`、`lib assign` 会写库里的文件：跑之前看有没有别人没提交的改动，做完请用户审过再提交。**料号由用户定，别编**；立创编号查到了才写。

0. 先找库里有没有：`lib search <型号>`、`lib search --lcsc C…`；要的是某种功能的件（带 USB 的 MCU、某个封装的 LDO）就 `lib search --pin USB_DP --status released`、`lib search LDO --footprint "SOT-23*"`、`lib search --category IC/电源/LDO`（库根目录有分类表 `categories.csv` 时），能用现成的就别新建。
1. `lib new <型号> --manufacturer <厂家> --package bga|soic|sop|qfp|son|qfn [--pins N] [--lcsc C…]`。
2. 读数据手册填三样（每一个数、每一个脚名都要有出处，拿不准的写进 part.toml 的 `notes`，别猜）：
   - **引脚表** `symbols/<型号>.pins.csv`：数据手册的引脚表逐行抄（PDF 表格可以用 PyMuPDF 按字符坐标抠，它自带的表格取字会把下划线挪位，别直接用）。大芯片至少两处互相核对：引脚号列表对球位图、功能表、电源 / 地分组表，数目和名字都对上再用。type 按功能表的方向（GPIO 写 io，模拟脚写 analog，电源 power，地 ground，用途不明的写 nc 并在 description 说明）；unit 按功能分（DDR、各组 GPIO、音频、电源、地……，参考原厂参考原理图的分法）；side：地址 / 控制、输入放左，数据、输出放右；group 把同一组的脚排在一起。
   - **封装** `footprints/<型号>.toml`：抄封装尺寸表的最小 / 标称 / 最大（D、E、A、A1、b、e、L，BGA 还有行列数和缺球位置）；数据手册注里有植球前球径写 `ball_nominal`；有推荐焊盘图时写 `pad`、`pad_span` 或 `land`。缺球位置对着底视图核一遍。
   - **part.toml**：描述、分类、数据手册链接、厂家型号，`notes` 写待核对的事。库根目录有 `categories.csv`（分类表）时，`category` 写表里的一个路径（比如 `IC/电源/LDO`）；表里没有合适的就问用户，别自己往表里加，不然提交审核会被拦。
3. `lib build <型号>`：看输出——符号每个单元几个脚、电源 / 地每个名字几个脚（和数据手册的电源分组表对）；封装的 IPC 计算过程、焊盘边到边；最后的检查「符号 N 脚和封装 N 个焊盘一一对上」、没有错误。再看 `preview/<型号>/` 里的图（能看图就看：符号每个单元、封装、3D）。
4. 立创有这颗料（先查立创编号）：`lib compare <型号> --lcsc C… --model`。球号 / 焊盘位置对不上是大事，逐个查清楚是谁错了；脚名截短、焊盘大小差一点是做法不同，照实告诉用户。
5. 结果告诉用户：生成了哪些文件、检查结果、和立创的差异、`notes` 里待核对的事；用户审过后再帮着提交到库（`git add` 逐个文件，别 `-A`）。
6. **接法规则**（芯片值得写的：电源芯片、收发器、带外部元件的模拟芯片）：在符号文件里加 `[hookup]`（格式见 PartsLib README，例子 `symbols/NCN5130.toml`）。**只照数据手册写，别照手上的设计写**——典型应用图逐脚看每个脚接什么（看清导线交叉处有没有点、跳线），外部元件表抄取值范围和额定电压，功能说明里「不用时接 X」写成几选一的 option；每条写出处（页、图、表）。写完：拿一个确认接对的工程跑 `hookup` 要全对，再把一个脚故意改错（两脚对调、电源脚换网）要报出来；然后请用户对着规格书核这张规则表。

**用户给的是 PADS 元件库**：要的是 PADS Library Manager 导出的 ASCII（第一行 `*PADS-LIBRARY-PART-TYPES-V9*` / `…-SCH-DECALS-V9*` / `…-PCB-DECALS-V9*`，扩展名 .p / .c / .d；二进制的 .pt9 / .pd9 / .ld9 请用户在 PADS 里选库 → Export 成 ASCII，三种都导出）。先在临时文件夹 `easyedatool lib --lib <临时库> import <文件夹> --preview` 看报告和预览图，没问题再导进真库。看报告：「读不懂的一行」「没导入」的器件类型、按名字猜的脚长（请用户把公共库的引脚图形一起导出就不用猜）都照实转告；导进来的都是草稿，料号、厂家型号请用户补。

## 别的常见活

- **看 EDA 里手画的板**：`info` → `check` → `drc`（不带规则文件就按工程里 EDA 的间距规则查、不查隔离带）→ `render --view layers`。
- **出下单文件**：先 `drc`，再 `fab <工程> -o <文件夹>`（里面的 zip 直接传嘉立创）、`bom`、`pdf`。工程里有铺铜没填充时 `fab` 当场算好（会提示）。
- **铺铜**：`gen`、`route` 已经自动算。用户在 EDA 里改过走线：`pour <工程>` 看和存的差多少，`pour <工程> --write` 写回（守规矩 1、4）。
- **板子布好了，只重画原理图**：`easyedatool gen 设计 --out <工程> --schematic-only`（加 `--layout pages`）。只换原理图，PCB 一个字节不动，器件沿用板子上的 Unique ID 和封装 id；跑完 `check` 要「逐脚差异 0」。用户开着 EDA 的话先请用户关掉这个工程。
- **让用户看着你画**：用户说想看、想盯进度，或者要跑 `route` 这种几十秒的活：先 `easyedatool view <工程>`（输出「预览窗口打开了」），再照常跑命令，不用另做什么。窗口不点「开始改」时只读文件，不用像 EDA 那样先关页面；同一个工程已经开着窗口就别再开。找不到窗口程序时（报「找不到预览窗口程序」）照常干活，告诉用户可以装 Flutter 编 `viewer/`。
- **用户想自己改**：告诉用户在预览窗口里点「开始改」。PCB 上：点器件选中，拖着挪，R 转 90°，B 翻到另一面，L 锁定。原理图页上：点引脚改接到的网络、断开、打 ×，点器件改值、删掉，点导线给网络改名，「加器件」加阻容感、LED、测试点或元件库的件（gen 生成的工程才能改原理图）。Ctrl+Z 撤销，改完点「改完了，交给 AI」。人改的时候别跑改工程的命令（规矩 10）。
- **处理审核意见**（`easyedatool review <工程>` 输出「审核意见：要处理的 N 条」，下面每条是「#编号 位号：意见」；edits.log 末尾也会列出）：一条条照意见改（改设计文件再 `gen`，改板子再 `route` / `pour --write` 等），改完一条就 `easyedatool review <工程> --answer <编号> "怎么改的"`（一句话说清改了什么，如「新加 R2 100k 上拉，U1.3 改接 EN」），输出「第 N 条意见（…）记下了回复」才算回复上；用户在窗口里确认或退回（退回的那条又出现在「要处理的」里，再看一遍意见）。意见看不懂或觉得不该改，就问用户，别乱改，也别不回复。输出里「审过以后又改了、勾已经不算的」是用户审过、后来又变了的器件，用户要重看，不用你做什么；用户审过的器件（`--json` 的 `ok`）没必要别动。
- **人在窗口里改过以后接着干**（工程里有 `.easyedatool/edits.log`，设计文件旁边有 `<设计>.layout.toml`）：先读 edits.log 看人改了什么。「原理图第 N 页 …」几行是人拖、转、画的（画法记在布局文件的 [sch] 里，不用管）。有「设计文件：加了禁布区 …」时，人在窗口里画了禁布框（写进了设计文件的 `[[regions]]`）：布线器不读设计文件的禁布区，接着 `route` 之前在规则文件里加一个一样的 `[[keepout]]`（同样的矩形和层）。gen 的输出有「注意：上次生成以后，原理图 … 在外面（嘉立创里？）改过」时，用户在嘉立创里改过那几页，这次生成照设计文件重写、改动没了：告诉用户，问要不要从 git 里找回来对着改设计文件。有「人从窗口跑了 route…」这类行时，人在窗口菜单里跑了改板子的命令（布线、重布某个网络、差分、等长、加粗）：板子以现在的为准，别把它改回去。有「窗口里退回到 … 那一版」一行时，用户把工程、设计文件、布局文件退回了那一版（git 里存成了新的一版）：从退回后的样子接着干，别把退掉的改动又做回去，除非用户说要。「设计文件：…」那几行是人在原理图上改的连接（画线、删线、加标签也算）、值、增删的器件，已经直接改在设计文件里了（`git diff` 设计文件也能看到）：以它为准接着改，别按你原来的打算把它改回去；觉得人改得不对就问用户。设计文件开头写着是脚本生成的（`# Generated by …`，edits.log 里有「注意：设计文件是脚本生成的」）时，先把这些改动搬进生成它的脚本，再重跑脚本，不然改动就冲掉了。再 `gen` 时器件留在人摆的位置、布好的线写回去（输出里有「布局文件 …：照它摆 N 个器件」「布局文件里的走线 N 段、过孔 M 个写回了工程」），新加的器件自动排进空地；别删布局文件（删了就回到自动摆法，人摆的全没了），也别手改它。要挪某个器件：改设计文件里它的 `pcb` / `angle` / `side`（改了的那个以设计文件为准，输出里列在「设计文件改了位置的按设计文件摆」），或者请用户在窗口里挪。人挪过器件后原来连着的线对不上（飞线和 `drc` 的「没连上」会显示）：补线用 `route` 时在规则文件 `[nets]` 写 `keep = ["*"]`，留住已布的线、只布没连上的；不写 keep 会把全部走线删了重布。`easyedatool layout <工程>` 看布局文件和工程是否一致。人在窗口里拖过原理图（`layout` 的输出有「原理图：照布局文件里记的画法画」）：再 `gen` 时原理图照人画的画，不再自动排版；你在设计文件里的改动 gen 自己对上去（删掉的器件连线去掉，新器件放进它那一块附近的空地，引脚换了网络就断开、补上标签，网络改名就改标签），输出里「原理图照布局文件里记下的画法画」下面列出改了什么；出现「原理图和设计文件还有 N 处对不上」就是没对完，跑 `check` 看是哪些引脚，告诉用户。新器件放的位置不好看，请用户在窗口里挪；别为了重新排版去跑 `layout --forget-sch`（人画的全没了），要的话先问用户。
- **把 PADS 板子搬进嘉立创**：用户要的是 PADS Layout 导出的 ASCII（`.asc`，第一行 `!PADS-…`；二进制 `.pcb` 还不认，让用户在 PADS 里 File → Export 成 ASCII）。先 `easyedatool info 板子.asc` 看「走线两端落在焊盘上：… 对不上 0 处」，再 `easyedatool import 板子.asc --out <空文件夹>`（文件夹名就是工程名）。看输出的自检：焊盘「位置不对 / 形状大小或开窗不对 / 孔不对 / 网络不对 / 缺的」都是 0、过孔和铺铜填充数相等、「内层不留铜的」对不上 0、每层走线长度 PADS 和读回一样，才算转对；「注意」照实转告用户。有同一块板的 OrCAD 原理图时加 `--sch 原理图.DSN` 合成一个工程，再看「原理图和 PCB 配对」和「逐脚比」两行：只在一边的器件、网络不一样的地方照实告诉用户（常见的是不贴件、改版后改过的网络名）。然后 `render <工程> --view layers` 出图，让用户在嘉立创里打开看（提醒：在嘉立创里重建铺铜会按嘉立创的规则重算）。
- **查 Altium 板子**（`.PcbDoc`，二进制的和文本格式 `|RECORD=…` 的都认）：`info 板子.PcbDoc` 看读了哪些、「没读」的照实转告；`drc`、`render`、`kicad`、`fab`、`view` 直接用。查安规（电气间隙、爬电）时规则文件按电路分网络类（AC 保险前 / 保险后 / N、DC 初级、次级……），类对类写公司安规表的数（加生产余量），要和 KiCad 对数就加 `[drc] creepage_style = "kicad"`，再 `kicad 板子.PcbDoc --rules 规则.toml --drc` 让 KiCad 跑一遍；两边不一样时先看是不是碰到圆弧走线（KiCad 自己导入 Altium 时圆弧是真圆弧，它的爬电不拿圆弧挡路、还会算出比直线间隙短的数）。
- **把 Altium 板子搬进嘉立创**：`easyedatool import 板.PcbDoc --sch 同一版的图.SchDoc --out <空文件夹>`。看自检：器件、焊盘（位置 / 形状 / 网络 / 缺的）、过孔、走线长度、铜皮面积都对上，原理图「连接自检」断开和短路是 0，「原理图和 PCB 配对」只在一边的器件、「逐脚比」网络不一样的地方照实告诉用户（常见的是不贴件、改版后改过的网络）；「同名封装画得不一样的拆成了几种」也转告。只有 PCB 时去掉 `--sch`。
- **把 Altium 原理图搬进嘉立创**：`easyedatool altium 图.SchDoc` 先看摘要（「没画的」「注意」照实转告：端口画成图形、贴着引脚的电源端口补了短线这些），再 `--out <空文件夹>`，看「连接自检」要「断开的网络 0，短到一起的 0」。有同一版的 PcbDoc 时用 `--netlist` 出网表，和 PCB 的焊盘网络对一下（网络名大小写可能不同：Altium 的 PCB 会改成大写）。一次一张 SchDoc，层次图还没做。
- **把 OrCAD 原理图搬进嘉立创**（原厂参考设计、老图纸）：`easyedatool orcad X.DSN` 先看摘要（「读不了的：0 处」才算读全，新格式和 16.2 老格式都认；报「no pages to import」说明给的是库文件或读不懂的版本，把摘要原样告诉用户）→ `easyedatool orcad X.DSN --out <空文件夹>`（文件夹名就是工程名，嘉立创按文件夹名认工程，别另给不一样的 `--name`）。看输出的「连接自检」：「断开的网络 0，短到一起的 0」才算对；「注意」里的重复位号、符号改过的器件、隐藏电源脚照实转告用户。再 `render <工程> --view sch` 出图看，用户手上有 OrCAD 导出的 PDF 就对着看。
- **查功率器件发热、走线载流**（开关电源、大功率驱动板）：在规则文件里写 `[thermal]`（格式见 `references/rules-format.md`）。器件参数照数据手册抄（常用件放进元件库 part.toml 的 `[thermal]`，以后不用再抄），工况（电流有效值、开关频率、关断电压电流……）问用户或按电路算，**别编**，估的数在结果里照实说是估的。大电流网络写 `from` / `to`（电流从哪个脚进、哪个脚出），工具把走线、过孔、铺铜当电阻网解出每段电流；只给电流的网络是按整网电流的保守估算。看结果：器件「超」的看是哪项损耗大（导通 / 开关 / Coss）和热阻怎么取的；网络「超」的照报出的位置加宽走线、加铜、多打过孔，改完再跑。要看整块板哪里热、器件挤在一起互相加热多少：加 `--map 热分布.png`（能看图就看图；预览窗口开着时温度直接叠在板上），器件有 ψJB 的写 `psi_jb` 才有板温 + ψJB 的结温；板面换热系数默认静止空气，装在密闭小壳里、有风扇的要问用户再改 `h_top` / `h_bottom`，结果照实说是估算。
- **查开关电源的版图**（DC-DC、PMIC、反激）：先 `easyedatool smps <工程> --suggest --png 电源.png`。看认出来的每路电源（芯片、电感、开关节点、回路里的电容）对不对，不对就把 `--suggest` 打出来的那段贴进规则文件的 `[smps]` 改，再加 `--rules` 跑。看结果：热回路「超」的看那几段——「绕远了：直线只有 x mm，中间隔着 …」说的就是挡住回流的铜（顶层被开关节点隔开、底层的地被别的线切开），建议把输入电容挪到芯片的 VIN 和 GND 脚边上、地平面别让走线切断；开关节点「过孔 / 多层」的能不跨层就不跨；安静网络挨太近的把 FB 走线挪开或换到隔着地平面的层；去耦不合格的就近加电容或把地打到最近的地平面。能看图就看 `电源.png` 和每路的放大图。数值是版图几何，不是仿真，照实说。
- **查高速线的反射和串扰**（DDR、SDIO / eMMC、SPI、时钟……）：先 `easyedatool impedance <工程>` 看叠层像不像真的（导入的板子常是默认叠层：每层介质一样厚）。问用户要板厂的叠层单（叠层阻抗表），照抄进规则文件 `[stackup]`；介电常数没写就拿阻抗表的一行反推（`impedance --stackup 规则.toml --layer 1 --field --width …` 对上它的阻抗）。驱动参数照芯片手册（上升时间、驱动强度 / 输出阻抗、片内端接、脚电容；差分接口的接收端差分端接写 `r_diff`，比如 MIPI / LVDS 100 Ω，USB 高速每根 45 Ω 写 `odt`），按网络分组写进规则文件 `[[si.group]]`（格式见 `references/rules-format.md`），没有就照实说用的是通用值。跑 `easyedatool si <工程> --rules 规则.toml --xtalk --png 波形.png`，看驱动脚对不对（输出里写了按什么定的），能看图就看图。过冲超的：加串联电阻（驱动端）或端接、减小线长 / 残桩、让阻抗连续（看「阻抗和主体差 15 % 以上的段」）；串扰超的：拉开间距（3 倍线宽以上）、缩短并排长度、换到带状线层、中间加地。用户要核对仿真本身时加 `--spice 文件夹` 再跑 `python tools/verify_si/compare.py 文件夹`（要装 KiCad）。没有 IBIS 时结果是线性通用模型、无损线，照实说。
- **用 IBIS 仿真**：芯片厂给的 .ibs 先 `easyedatool ibis 文件.ibs` 看器件名、脚、模型、波形重算差（> 1 % 先别用）。绑进元件库：文件放 `<库>/sim/<型号>/`，part.toml 加 `[sim] ibis = "sim/<型号>/x.ibs"`、`ibis_component = "<[Component] 名>"`（封装焊盘号和 IBIS 脚名不一样时 `[sim.ibis_pins]` 焊盘 = 脚名），`easyedatool lib check <件>` 看「IBIS …：[Component] …，N 个信号脚有模型」和焊盘对不对得上。板子上的器件要能认回库里的件（gen 用库件生成的自带料号 / Manufacturer Part / 立创编号属性；别的板子没有就在规则 `[si.parts.U1] part = "料号"` 或直接 `ibis = "文件"`）。`si` 自动找库（`--lib`、环境变量、工程旁边的 `easyedatool.toml`）。DDR 这类 I/O 脚：驱动强度写分组 `model`，片内端接（ODT）写 `rx_model`（都是 IBIS 里 `[Model Selector]` 的模型名）。IBIS 文件一般有保密协议：放公司元件库，不进别的仓库。
- **找某个器件 / 网络**：`pads --part U3`；`render --view layers --net SPI_MOSI --window x0,y0,x1,y1 --ppmm 60`。

## 别做

- 别手改 `.epcb2` / `.esch2` 里的记录（ticket、删除记录、铺铜填充这些规矩很多）：改设计文件重新 `gen`，或者让用户在 EDA 里改。真要改：二进制读写、保持 LF（规矩 9），改完 `check`。
- 别把 `drc --clearance 0.152` 的结果当成 EDA 的结论：那是所有铜皮一个间距（旧脚本 drc.py 的做法）；不带它才按工程里 EDA 的规则表。
- `pair` 只在一层上布、不打过孔，每根网络在那一层要正好两个焊盘（中间有串阻、共模电感的要分段，还不支持）；成品密板上重布常常布不通，那是地方不够，别硬改规则凑。写回前先 `pair` 不带 `--write` 看报告。
- `tune --write` 之后提醒用户在嘉立创里重建铺铜（新走线压着旧填充，嘉立创 DRC 会报 Copper Region(Filled) to Track）；「还差」的网络是直线段上放不下，照实告诉用户，别硬塞。
- 阻抗先看叠层对不对：`impedance` 第一段是工程里的叠层，导入的 PADS 板常是占位值（每层一样厚），那样算出来的阻抗没意义，先请用户在嘉立创层管理器里设成实际叠层，或用 `--stackup` 选立创标准叠层。嘉立创的计算器对「上下介电常数不一样」的内层（立创标准多层叠层的内层都是）、线距小于 5 倍铜厚的差分带状线算不出来，这些用 `--field` 的场求解结果；它的耦合微带公式比场求解高约 5%，用户要准的线宽时给场求解的数，要和嘉立创界面一致时给嘉立创的数，两个都说清楚是哪个。
- 别用桥（`overwriteNetRules`）或手改 `RULE_SELECTOR` 给差分对 / 等长组指定规则：规则要同时写在对、组和它们每根网络的指定上嘉立创才按它查（见 `references/eda.md`）。用 `constraints --from 约束.toml --write`（格式见 README「差分对和等长」）。
- 网格铺铜（EDA 里设成网格的）不算，留着工程里存的。
- 别拿 `render` 的图代替 `check` / `drc`：看图看不出差 0.01 mm 的间距和接错的脚。

## 快速自测（第一次用、或怀疑环境有问题时）

在一个临时文件夹里跑（`<目录>` 换成真实路径，`examples/` 在本目录下）：

```
easyedatool gen examples/mp157demo.toml --out <目录>/MP157Demo
easyedatool check <目录>/MP157Demo --rules examples/mp157demo.rules.toml
easyedatool route <目录>/MP157Demo --rules examples/mp157demo.rules.toml
easyedatool drc <目录>/MP157Demo --rules examples/mp157demo.rules.toml
```

应当：`gen` 打出工程路径，原理图自检「出图框 0，压标题栏 0，重叠 0」；`check` 「全部通过」。23 个元件库器件的符号和封装在 `examples/lib`，`examples/easyedatool.toml` 指向它。`route` 用的规则写了 `keep = ["*"]`，已有走线留着，只补没连上的。
