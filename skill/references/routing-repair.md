# 按实际铜通道局部重布

用于已经布好大部分的板，尤其是整板重启后总有几个网络轮流断开的情况。先保留当前最好 PCB，不要为重试把它拆光。这个流程是原生 Rust，详细布线仍由现有 CPU 路由器执行；无需 Python、CUDA 或显卡。

项目已将焊盘内过孔等质量项列为硬错误时，`routing_quality_errors` 的网络和实际位置同样作为重布目标；普通建议提示不会触发拆线。布通计数为 0 未连接，也必须继续处理这些硬错误，不能将电气连通当成制造工艺检查完成。

## 步骤

1. 用正式规则运行 `drc <工程> --rules <规则> --json before.json`，确认实际还有哪些断网或铜冲突。不要凭飞线视觉数量判断剩余连接数。
2. 核对本次允许重布的网络范围。`[nets] keep` 是硬约束，保留 RF、晶振及其他不允许改变的铜；`keep = ["*"]` 会保留所有网络，修复器不能越过它。原规则中非空的 `only` 同样限定可重布网络。需要改范围时另存规则副本，遵守已有授权，不改变线宽、间距、板边、过孔和工艺要求。
3. 运行：

   ```text
   easyedatool route-repair <工程> --rules <完整规则.toml> --out <新的空目录> --attempts 32 --seed 1000
   ```

4. 看每次「局部重布 N：选择 M 个网络，剩余连接 X，DRC 硬错误 Y」。它从实际断网端点和铜冲突出发，选择附近的铜线、过孔所属网络，逐步扩大重布范围，其余网络保留。同一组网络的不同重布顺序分别试算，不当成重复候选丢弃。允许保留几种没有增加硬错误或剩余连接的路径，避免只沿一条失败路径反复重试。
5. 每个候选都重算铺铜，并以原始完整规则检查全板。还检查外部 `no_tracks`：旧线被保留、却穿过新加的层禁布矩形，同样计入硬错误并参与修复，记录在 `drc.json` 的 `routing_keepout`。矩形限制走线中心，不禁止过孔和铺铜。局部路由的 `only` 选择不会缩小 DRC 范围；中间 `route --no-drc` 只关闭重复的自动检查，不能关闭最后的完整 DRC。
6. 检查 `<输出>/report.json`。成功须同时满足 `complete: true`、`best.complete: true`、`best.remaining_connections: 0`、`best.unconnected_spots: 0`、`best.hard_errors: 0`、`source_unchanged: true`，并看到「全部布通，完整 DRC 通过」。`best.epcb2` 才是保留的最佳副本；不是最后一次尝试必然最好。

「预算内尚未全通，不能作为完成结果」表示还没完成。保留报告，说明真实剩余连接与硬错误，再决定后续搜索；不要把进程退出码 0、较短走线或一次局部 `route` 的布通计数当成全通证明。

## 参数与产物

| 参数 | 默认 | 含义 |
|---|---:|---|
| `--attempts` | 32 | 最多实际试布次数；0 只检查原板，最大 256 |
| `--neighbors` | 4 | 每个失败端点附近逐步选 1 到多少个阻挡网络 |
| `--beam` | 4 | 保留多少个没有变差的布线路径分支 |
| `--seed` | 1000 | 固定输入和种子，重现选择、重布顺序与原生 PCB |
| `--rip-passes` | 6 | 每个局部候选内部的拆线轮数 |
| `--search-budget-scale` | 16 | A* 搜索预算下限，只增预算，不放宽制造规则 |

`source-reference/` 保存未修改的输入及完整 DRC；`000/` 等目录保存候选 PCB、实际路由规则、路由日志、全板 DRC 和 `attempt.json`。重布只清除副本里的旧铺铜填充，再按新铜重算，不删除焊盘、铺铜定义、锁定状态或板框。器件、焊盘几何与网络必须和输入完全相同。

采用结果时按项目的设计 / 布局同步流程保存，重新核对原理图和 PCB。涉及屏蔽罩、连接器、禁布区的消融实验，恢复这些结构后必须重新布线和完整 DRC；无屏蔽罩全通不能代表带罩已经通过。

单个贴片焊片、单个测试焊盘不会再建立细间距芯片的保护带；多焊盘芯片的原有保护带仍保留。这项分类修复不缩小真实铜间距，不允许走线越过 `no_tracks`。
