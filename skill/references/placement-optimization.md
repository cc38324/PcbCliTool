# 多候选布局与 CPU/GPU 评分

本流程用于优化布局算法、比较候选，输入工程只读。它不声明数学上的全局最优。评分近似和实际布线结果分别保存，不能将评分降低或 GPU 加速视为已经布通。

## 运行

```text
easyedatool place-opt <工程或.epcb2> --config examples/place-opt.toml --rules <项目规则.toml> --out <新的空输出目录> --backend cpu
```

当前发行包包含 CPU 评分后端。GPU、compare 与 auto 的设备选择仅适用于明确提供 GPU 后端的程序版本；本版不能把 CPU 评分报告当作显卡加速结果。

GPU 程序的 `--backend compare` 对相同候选分别计算 CPU/GPU 分值，逐项完全一致才继续；有差异立即报错。`gpu` 强制使用 GPU，不可用时失败；`auto` 不可用时回退 CPU并在报告中注明；`cpu` 不创建设备。支持的底层为 Vulkan、Metal、DirectX 12，当前设备和平台仍须实际验证。

做全局布局实验时，普通旧走线不能限制器件的新位置。先在副本上只保留 RF/晶振等明确保护的铜（配置 `rounds=0`、`route_finalists=0`、`unrouted.grid=0`，由 `place-opt` 输出原位置的拆线副本；不手改原生记录），必要时用 `pour <副本> --write` 重算地平面，再对这份未布通候选启用 `unrouted`。命令必须加 `--reference <原板>`：工具验证器件、焊盘网络、原位置和规则一致，用未拆线原板的 DRC 作对照，候选比原板差时保留原板。`reference_source / reference_sha256 / reference_unchanged` 记录对照快照。不能把拆线后83条减少到11条，称为比原板10条更好。

要比较冷启动和连续工作，可加 `--benchmark-repeats 5`。报告分列准备/CPU硬约束、CPU评分、GPU初始化、GPU计算及传输耗时；GPU初始化不能从首次运行成本中省略。小板、少量候选未必适合 GPU，按完整流程耗时选择后端。

未通探针的可动焊盘障碍按原始焊盘、候选位置/转向和膨胀距离缓存复用；不同网络、线宽与过孔半径仍按各自规则扣除。CPU/GPU 共用这项优化，缓存不改变采样网格和碰撞判定。比较显卡收益时须使用同一版本，不能把旧 CPU 的重复几何计算时间算成 GPU 的收益。

## 配置（TOML）

配置字段不认识会拒绝，单位毫米、Y向上。

| 字段 | 含义 |
|---|---|
| `movable` | 必填的可动位号，可用 `* ?`；没有匹配会拒绝 |
| `fixed` | 额外固定位号，优先于 movable；未列入 movable 的器件也固定 |
| `keep_nets` | 每个试布候选保留的原铜，匹配器件必须固定；PCB已有锁定铜也保留 |
| `ignore_nets` | 仅从便宜评分中排除，不改变网表和真实布线/DRC；铺铜网络自动从线长估计中排除 |
| `candidates / elites / rounds` | 每轮新增候选预算、精英数量、搜索轮数；轮数0仅保留原布局 |
| `seed` | 固定搜索种子；相同输入、规则和预算应生成相同位置、分值和候选PCB |
| `step / radius` | 平移步长、相对源器件中心的最大移动半径；step须为0.001mm整数倍 |
| `spacing / edge` | 器件外包络间距、可动器件外包络到板边距离；固定端口可在板边 |
| `rotations` | 相对于源器件方向的允许增量，0/90/180/270度 |
| `bounds` | 可选可动外包络整体范围 `[x0,y0,x1,y1]` |
| `cell` | 拥塞估算格距，0.001mm整数倍；总格数上限16384，与实际路由网格独立 |
| `congestion_weight / pin_weight` | 快速评分中拥塞、引脚压力的权重；属于近似目标，不替代实际布线排序 |
| `route_finalists` | 0只评分；正数为额外试布候选数，通过硬约束的原布局另作对照，必须给 --rules |
| `feedback_rounds` | 依据实际未连通网络，再搜索并试布的轮数；全通后关注较长网络；0关闭反馈 |
| `route_rip_passes / route_restarts / route_optimize_passes` | 所有候选共同的布线计算预算；不修改制造间距、线宽、过孔和层数 |
| `via_penalty` | 实际全通布局的过孔代价，换算成等效线长毫米 |
| `[unrouted].grid` | 0关闭；正数启用未连通连接的网格寻路评分，单位mm，必须给正式 --rules |
| `[unrouted].margin` | 每条待连连接的端点外包框向外扩的寻路窗口，默认1.5mm；窗口小可能漏掉远处绕路 |
| `[unrouted].max_steps` | 波前扩展预算，默认1024；耗尽与窗口内无路分别记录 |
| `[unrouted].keep_copper` | 默认true：保留已有走线和过孔，只补未连接处；移动焊盘不能碰异网保留铜。false允许拆掉涉及可动器件的网络，原始断点只作近似引导，仍须检查全部网络 |

通孔器件、PCB锁定器件和连接锁定铜的器件不能加入可动集合。不会交换引脚网络或更改原理图。

启用 `unrouted` 后，目标来自原生 DRC 的未连通铜分组。保留铜模式直接复用原生飞线的最小生成树，端点可以是引脚或已有过孔；已扇出到过孔的铜分组从过孔继续探测，不从芯片脚重复出线。重布近似模式按组间引脚选连接。CPU/GPU 使用相同的四方向、多层、贯穿过孔可达性探针，逐候选、逐待连连接并行计算；已连通网络退出线长优化目标。目标字段为 `unrouted_missed`、`unrouted_gap_um`、`unrouted_steps`；`unrouted_exhausted` 单列预算耗尽数量。每轮实际试布反馈后重新提取未通连接，并重新计算所有起始候选分数，不能混用旧目标的分数。已经全通时跳过位置搜索。

探针默认保留所有既有铜作为物理上下文，再按候选位置放回焊盘；制造线宽、间距、过孔直径从同一份规则读取。保留铜与移动焊盘的异网碰撞属于硬约束，试布前即拒绝。`keep_copper=false` 才忽略接到可动器件的旧铜（清单在 `omitted_movable_nets`），该模式可能产生额外待连连接，最终完整试布必须核对全部网络。探针没有同时预留所有待连连接的通道，使用局部窗口和采样网格，不能证明所有网络可以同时布通。游离铜组另记 `floating_groups`，交给完整 DRC；首版探针遇到盲埋孔拒绝运行，可设 grid=0 使用原流程。

可选数组条目：

```toml
[[group]]
parts = ["U2", "C12"]          # 刚性组，整体平移/旋转；成员必须可动且不可重复分组

[[region]]
parts = ["U2", "C12"]
rect = [1.5, 1.5, 7.0, 8.0]   # 全部外包络须在区域内

[[blocked]]
rect = [1.1, 1.0, 1.5, 18.2]
side = "top"                  # top / bottom / both，默认both；禁止器件外包络进入

[[near]]
pin = "C12.1"
target = "U2.8"
max = 2.0                     # 焊盘中心直线距离限制，不能代替真实去耦回路检查

[[net_weight]]
nets = ["FLASH_*"]
weight = 2                    # 0..1000，后匹配项优先，仅影响便宜评分
```

关键RF、电源回路、天线净空和3D罩子约束须由项目明确给定。首版搜索不自动推断这些电路要求，2D硬约束不包含厂家CAD机械签核。

## 怎么判断成功

输出位于指定目录：

- `report.json`：源快照哈希、配置、位号顺序、原布局与最好候选、搜索曲线、实际试布、设备与计时。
- `search-N.json`：每轮搜索结束立即存档；后续试布失败也保留已经算好的候选。
- `feedback-focus-N.json`：反馈轮优先搜索的器件；未通网络两端固定时，也纳入端点附近的可动器件，邻域取 `cell + spacing`。
- `best.epcb2 / best.layout.toml / best.poses.json`：独立候选PCB及其几何。只评分时删去非保留的旧铜，避免移动后的旧线路冒充已连接。
- `candidates/<id>/`：每个实际试布候选的PCB、统一的`trial.route.toml`、`route.log`、`drc.json`、`drc.log`、`trial.json`。
- `source-reference/` 和报告 `source_reference`：未拆线、未重布的输入快照及其完整 DRC；也参与最终保留选择，防止输出比原板更差。
- `trial-keep-nets.json` 和报告 `trial_keep_nets`：本轮实际保留的铜，默认修复模式为 `*`；公开派生保留策略，不能暗中改变对照条件。
- `unrouted-baseline.json / unrouted-best.json`：有实际试布时分别重新检查原板对照与最终输出的真实断点；仅评分时属于搜索场景。含真实端点、起终点有效采样格数、可达格数、步数、剩余格距估计和状态。`source_not_sampled / target_not_sampled` 是端点未落入采样空间，不能宣布物理无解；`blocked_in_window` 只说明该窗口内未找到路；`budget_exhausted` 是预算耗尽。

实际排序优先检查错误，再比较独立剩余连接数（各网络铜分组数减1之和，非飞线端点数）、未连接端点数，最后比较等效线长代价。耗时只记录，不参与排序，以免机器负载改变选中的方案。限预算没布通只说明本次试算未完成，不证明布局物理上无解。位置搜索保留不同候选和原布局；实际试布过的最好方案始终留档。只评分且分数完全相同时保留原布局，避免没有收益的改动。

`best.layout.toml` 是候选的独立几何记录。采用结果时须通过正常编辑流程同步设计与布局，并重新生成、核对；不能只把该文件覆盖回原工程就认为设计已经同步。

只评分时输出「仅完成布局评分，尚未验证实际布通；输入工程未修改」。此时不能宣布布通、生产释放或找到全局最优。

启用试布后，`route_tested` 表示已试布；只有「实际布线及 DRC 通过；输入工程未修改」以及 `report.json` 的 `route_validated: true`、`complete: true` 同时成立，才表示该候选通过本次规则检查。否则命令返回失败，保留报告，输出「实际布线尚未全部通过」。仍须核对项目未编码的电气、射频和机械约束。

使用 `--reference` 时，`source-reference/` 保存的是指定的未拆线原板；候选输入和对照原板都要保持哈希不变。诊断和位置评分属于当前搜索阶段的未通场景，实际好坏以对应候选和原板的完整 DRC 为准。

`--backend compare` 还应看到「CPU/GPU 一致候选 N」且N大于0，报告有真实适配器。没有 GPU 的机器不能把跳过设备测试写成GPU验证通过。

## 基准方法

固定工程快照、物理规则、原铜保留策略、搜索种子和计算预算；比较旧布局、多起点近似评分、加入实际布线反馈三个版本。至少包含小板、密集模组和器件较多的板；保留未参与调参的样板。记录完整耗时、首次全通、剩余连接、硬错误、过孔与总长。不要只挑最好的一轮或只报告内核耗时。

未通寻路基准应使用确实含待连连接的冻结 PCB，CPU/GPU 各以独立进程至少运行3次并交替顺序，另跑 compare 核对全部有效任务。分别报告进程墙钟（含初始化、数据准备、传输与诊断）、寻路计算和真实试布结果；当前 CPU 参考后端逐任务串行计算，比较结果不能外推为优于使用全部 CPU 核心的实现。正式计时应在编译和其他试布结束后运行。屏蔽罩等约束的消融实验须同时移除对应焊盘和禁布区，并以完整 DRC 的连通性作结论；恢复屏蔽罩后必须重新检查。

候选数量和权重是配置项；不要在Rust代码里写BeamMesh的位号、坐标和固定路线。已有 `gen / place / route` 的流程不自动启用本优化器。

## 初版线长评分实测（2026-11-03，未启用未通寻路探针）

Windows、本机 NVIDIA T600 Laptop GPU、Vulkan，三个独立后端进程均执行同样的搜索及三次重复批量评分。以下是一次实测的完整进程墙钟时间，包含设备初始化和数据传输，不能推算成其他设备的性能承诺。

| 样板 | 器件数 | CPU | GPU | 逐项核对的评分次数 |
|---|---:|---:|---:|---:|
| Demo | 6 | 0.117 s | 2.260 s | 193 |
| BeamMesh | 100 | 0.252 s | 2.147 s | 321 |
| KNXACBridge | 172 | 0.381 s | 2.243 s | 321 |

三组的 CPU、GPU、compare 搜索档案、分值、排序和最终原生 PCB 哈希一致，源 PCB 未改变。这个规模下 GPU 更慢，所以默认 CPU；`auto` 只处理设备不可用的回退，不是性能自动选择器。KNXACBridge 这里只做局部可动电阻的评分回归，未作为新的全板布线结果。

BeamMesh 同一份源快照、规则、保留 RF/晶振铜和布线预算下，原布局剩余 11 条独立连接、127 个过孔、377.8 mm；反馈候选剩余 10 条、120 个过孔、348.1 mm，几何/工艺硬错误均为 0，仍然未全通。不能将这个受限预算的对照，等同于超过了所有历史长时间布线结果。

注意：这里“11条”是原位置拆线重布后的值；输入原板本来就剩10条。因此该结果没有证明比输入原板更容易布通。之后增加 `source_reference` 和未通寻路目标，均以原板实际断网为基准。

Demo 的低线长评分候选出现丝印问题，完整试布最终保留了 DRC 通过的原布局。两例都保留失败候选，便于继续改进代理目标和约束，不能只展示更低的评分。

本版是多起点、精英保留、成组移动和布线反馈搜索；后续连续优化/梯度内核可复用当前评分与对照接口。完整详细路由仍在 CPU 上运行。

## 未通目标实测（2026-11-03）

冻结的 BeamMesh 原板有8个未通网络、10条独立待连连接，136个过孔、410.1mm走线，间距/板边等硬错误0。10条中的7条从已有过孔继续，评分直接使用这些真实飞线端点。

保留既有铜、18个可动普通器件的769候选搜索中，840次有效未通探针没有降低未到达数；4个位置候选的完整试布仍为10条、硬错误0，未超过原板。输入仍保留原样。

另做全局实验：保留RF/晶振等关键铜，其余普通铜在副本上移除，再铺地平面，从83条待连连接开始评分。两轮共有517个搜索候选记录、6428次未通探针，7个方案完整试布；同预算原位置与最好候选均剩11条。最好候选线长约364.7mm、126个过孔，虽然较短，仍比未拆线原板的10条差，因此不作为优化成果。用 `--reference` 可自动保留更好的原板。

这证明未通评分和拒绝退化的闭环已建立，没有证明当前搜索已经找到更易布通的 BeamMesh 布局。后续算法须继续处理通道竞争与过孔/走线重排，不能只扩大候选数量或展示CPU/GPU分值一致。

## 实际铜通道重排的后续结果

另加原生 `route-repair`，从失败端点周围实际铜线、过孔所属网络选择局部重布组，保留不同的未变差路径，并逐次跑完整 DRC，详见[局部重布说明](routing-repair.md)。它可接在原板或布局候选的详细布线之后，原有 `route` 不自动启动这项多候选搜索。

2026-11-03 无屏蔽罩 BeamMesh 冻结副本剩 2 条连接；Rust 版按种子 20261103 试布 15 次后全通，112 个过孔、427.8 mm，完整 DRC 硬错误 0。逐次选网、顺序与最终 PCB 字节和实验一致；全过程未移动器件。改善来自实际路由调整，不是 GPU 近似评分提升。

同日已在 Windows 的 WSL2 / T600 上运行 NVlabs Cypress 原版 CUDA 算法，6 组参数中 1 组未收敛；其余布局补上原生器件距离等约束后，实际试布最好仍剩 4 条。因此不能将较低的交叉 / 线长代理分数称为已改善布通，更不能把此次无罩全通归因于 Cypress。

恢复屏蔽罩后另行验收也已通过：原 22 个接地器件、201 个焊盘全部恢复，未移动任何器件；修正路由器把单个焊片当成细间距芯片、在各层挡住宽电源线的错误，再按实际铜通道局部重布。最终 137 个过孔、458.5 mm，完整 DRC 硬错误和独立剩余连接均为 0，五段罩墙下无顶层线；原 RF、晶振与开关节点铜逐段保持一致。保存到布局后连续两次项目重建 PCB 字节相同，原理图 ERC / 逐脚网表核对通过。全通来自路由建模修正和 CPU 详细布线，未证明 GPU 布局优于 CPU。
